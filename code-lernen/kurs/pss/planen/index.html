Warum man Software plant

Ziel dieser Lektion

Du kannst begründen, warum Planung Kosten spart, und kennst Spaghetti-Code, technische Schulden, CRUD, KISS, Modularität und die 3-Schicht-Architektur.

Der Stoff

Hobby gegen Firma

Ein privates Projekt darf nach „Ausprobieren und Ändern“ entstehen. Software in einem Unternehmen muss mehr können: Sie muss zuverlässig laufen, wartbar sein (andere und du selbst in einem Jahr verstehen sie noch) und skalieren (mit mehr Nutzern und Daten zurechtkommen). Das schafft niemand ohne Plan.

Ein Beispiel, wie es schiefgeht

Ein Azubi soll eine Kundenverwaltung bauen, eine CRUD-Anwendung: Create (anlegen), Read (anzeigen), Update (ändern), Delete (löschen). Er fängt sofort an zu programmieren (Code-and-Fix), benutzt globale Variablen, mischt die Rechenlogik mit der Oberfläche und kommentiert kaum.

Nach ein paar Wochen ist der Code Spaghetti-Code: Niemand findet mehr Anfang und Ende eines Fadens. Fehler häufen sich, Daten widersprechen sich (ein Kunde steht mit zwei Postleitzahlen in der Datenbank), und jede Änderung an der Datenbank betrifft das ganze Programm. Er steckt in technischen Schulden: Wie bei einem Kredit war der schnelle Weg erst bequem, jetzt zahlt er Zinsen in Form von Fehlersuche und Umbau.

Die Fachbegriffe aus dem Beispiel

BegriffBedeutung
Globale Variableüberall im Programm les- und änderbar; man weiß nicht mehr, wer sie wann verändert hat. Besser: lokale Variablen, die nur in einer Funktion gelten
Trennung der Belange (Separation of Concerns)Oberfläche, Geschäftslogik und Datenhaltung getrennt halten, damit eine Änderung nicht alles andere mitreißt
DatenkonsistenzDaten sind korrekt und widerspruchsfrei
Technische Schulden (Technical Debt)Mehraufwand später, weil jetzt eine schnelle, schlechte Lösung gewählt wurde

Was strukturierte Planung bringt

PrinzipKurz gesagt
Modularitätkleine, abgeschlossene Bausteine mit genau einer Aufgabe; einzeln test- und austauschbar
KISS (Keep it simple, stupid)die einfachste klare Lösung wählen, nichts unnötig verkomplizieren
3-Schicht-ArchitekturPräsentation (Oberfläche), Logik (Geschäftsregeln), Datenhaltung (Datenbank) getrennt; so lässt sich etwa die Datenbank tauschen, ohne alles neu zu schreiben
Coding Conventionsgemeinsame Regeln für Namen, Einrückung und Klammern, damit Code im Team aussieht wie von einer Person

Fehler werden mit der Zeit teurer

Ein Fehler, den man in der Planung findet, kostet eine Änderung im Dokument. Derselbe Fehler nach dem Deployment (Auslieferung beim Kunden) kostet Fehlersuche, Codeänderung, neue Tests, neue Auslieferung und vielleicht Schaden beim Kunden. Erfahrungswerte sprechen von bis zu hundertfachen Kosten. Darum lohnt sich Planung, auch wenn sie am Anfang Zeit kostet.

Die Werkzeuge der Planung: Modell und Pseudocode

Wie ein Architekt vor dem Hausbau Baupläne zeichnet, nutzen Entwickler Modelle (meist in UML) und Pseudocode. Beide trennen die Logik (das Was: was soll passieren, wie hängt es zusammen) von der Implementierung (das Wie: der Code in einer bestimmten Sprache). Ein typischer Weg in einem Team:

  1. Anwendungsfalldiagramm: Wer macht was mit dem System?
  2. Klassendiagramm: Welche Daten und Klassen gibt es?
  3. Aktivitätsdiagramm: Wie läuft ein Vorgang ab?
  4. Pseudocode: Die wichtigen Algorithmen ausformulieren und auf Denkfehler prüfen.
  5. Erst dann programmieren, zum Beispiel in Java oder Python.

Typische Stolperfallen

Achtung

„Programmieren“ und „Codieren“ sind nicht dasselbe. Programmieren ist das Planen und Beschreiben aller Arbeitsschritte, Codieren ist das Übersetzen dieses Plans in eine Programmiersprache.

Prüfe dich

  1. Was beschreibt der Begriff „technische Schulden“?
    • Den Abschreibungswert alter Hardware in der Bilanz
    • Den späteren Mehraufwand durch heute gewählte schnelle, schlechte Lösungen
    • Die laufenden Lizenzkosten für Entwicklungsumgebung und Server
    • Rechnungen der IT-Abteilung, die noch nicht bezahlt wurden
  2. Wofür steht CRUD?
    • Create, Read, Update, Delete
    • Code, Run, Use, Debug
    • Copy, Read, Upload, Download
    • Create, Run, Undo, Deploy
  3. Welche drei Schichten trennt die 3-Schicht-Architektur?
    • Hardware, Betriebssystem, Anwendung
    • Frontend, Backend, Cloud
    • Präsentation, Logik, Datenhaltung
    • Planung, Code, Test
  4. Wann ist ein Fehler am günstigsten zu beheben?
    • Im Wartungsvertrag
    • Das ist immer gleich teuer
    • Nach der Auslieferung
    • In der Planung

PAP und Struktogramm: vom Plan zum Pseudocode

Ziel dieser Lektion

Du liest und entwirfst Sequenz, Verzweigung, kopf- und fußgesteuerte Schleifen sowie Methodenaufrufe im PAP und Struktogramm und prüfst sie direkt im Pseudocode-Interpreter.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Der letzte Schritt vor dem echten Code

Vom Lastenheft über Use-Case und Aktivitätsdiagramm sind wir jetzt auf der Ebene eines einzelnen Algorithmus angelangt. Bevor du ihn in Java oder Python schreibst, zeichnest du ihn als Programmablaufplan (PAP) (Symbole mit Pfeilen) oder als Struktogramm (geschachtelte Kästen nach Nassi-Shneiderman, ohne Pfeile) – und prüfst ihn im Pseudocode-Interpreter.

PAP und Struktogramm direkt im Vergleich

BausteinSymbol im PAPDarstellung im Struktogramm
Start / EndeOval (abgerundetes Rechteck)Anfang und Ende des gesamten Kastens
Anweisung / RechnungRechteckeinfacher rechteckiger Block
Ein- / AusgabeParallelogrammBlock mit Eingabe: / Ausgabe:
Verzweigung (if/else)Raute mit Ja-/Nein-PfeilKasten mit Dreieck oben, links Ja, rechts Nein
SchleifeRaute + Rückwärtspfeil nach obenKasten mit Rand links (oben = kopfgesteuert, unten = fußgesteuert)

Verzweigung im Struktogramm: Versandkosten

Lies von oben nach unten: Da 3998 < 5000 ist, läuft der rechte Zweig (versand <- 495), danach werden beide addiert (4493 Cent).

warenwert <- 3998
warenwert >= 5000 ?janein
versand <- 0
versand <- 495
gesamt <- warenwert + versand
Ausgabe: gesamt

Kopfgesteuerte Schleife: Warenkorb summieren

Die Bedingung steht oben: Bei einem leeren Warenkorb (LÄNGE = 0) läuft der Rumpf kein einziges Mal.

summe <- 0
i <- 0
solange i < LÄNGE(preise)
summe <- summe + preise[i]
i <- i + 1
Ausgabe: summe

In der Praxis

Jeder Kasten im Struktogramm wird 1:1 zu einer Zeile Pseudocode. Klicke auf „Ablauf verfolgen“, um die Schleife live zu prüfen.

Fußgesteuerte Schleife: Eingabeprüfung im Bestellformular

Eine fußgesteuerte Schleife prüft erst nach dem Durchlauf – sie läuft also mindestens einmal. Typisch ist das Mengenfeld im Shop: Erst muss der Kunde etwas eingeben, dann prüft das Programm, ob die Menge positiv ist.

Wichtige Prüfungsfalle: Im PAP und Struktogramm steht oft die Durchführungsbedingung (solange menge <= 0 → wiederhole, solange ungültig). Im Pseudocode WIEDERHOLE … BIS steht die Abbruchbedingung (BIS menge > 0 → stoppe, sobald gültig). Beide meinen dieselbe Schleife – nur umgedreht!

Fußgesteuert im Struktogramm (Durchführungsbedingung)

Eingabe: menge
solange menge <= 0
Ausgabe: „Menge übernommen“

Dieselbe Eingabeprüfung als Pseudocode (Abbruchbedingung)

Pseudocode
1
WIEDERHOLE
Fußgesteuert: läuft mindestens einmal.
2
  LIES menge
Kunde tippt im Bestellformular eine Menge ein.
3
BIS menge > 0
Abbruchbedingung: erst bei positiver Menge geht es weiter.
4
SCHREIBE "Menge übernommen:", menge
In der Praxis

Bestellformulare, PIN-Eingaben und Konsolenmenüs nutzen genau dieses Muster: erst fragen, dann prüfen.

Typische Stolperfallen

Achtung

Achte bei WIEDERHOLE … BIS immer darauf, ob nach der Durchführungsbedingung („solange falsch“) oder der Abbruchbedingung („bis richtig“) gefragt ist.

Prüfe dich

  1. Welche Schleifenart läuft garantiert mindestens einmal?
    • Kopfgesteuerte Schleife
    • Zählschleife mit Start > Ende
    • Fußgesteuerte Schleife
    • Keine Schleife läuft garantiert
  2. Im Struktogramm steht unten solange menge <= 0. Wie lautet die passende Abbruchbedingung in WIEDERHOLE … BIS?
    • BIS menge = 0
    • BIS menge <= 0
    • BIS menge > 0
    • BIS menge < 0
  3. Welches PAP-Symbol steht für den Aufruf einer Methode (Unterprogramm)?
    • Abgerundetes Rechteck (Oval)
    • Parallelogramm mit schrägen Seitenlinien
    • Rechteck mit doppelten senkrechten Seitenlinien
    • Raute mit zwei beschrifteten Ausgängen
  4. Der Warenkorb ist leer (LÄNGE(preise) = 0). Wie oft läuft SOLANGE i < LÄNGE(preise) (mit i = 0)?
    • Genau einmal (1 Durchlauf)
    • Zweimal (2 Durchläufe)
    • Keinmal (0 Durchläufe)
    • Endlos viele Durchläufe

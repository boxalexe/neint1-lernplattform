Vertiefung: JSON, async/await und Webseiten (DOM)

Ziel dieser Lektion

Du tauscht Shop-Daten per JSON aus, verstehst asynchronen Code mit Promises und async/await und weißt, wie JavaScript im Browser auf Klicks im DOM reagiert.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

JSON: die Sprache zwischen Frontend und Backend

Wenn ein Webshop Artikel vom Server lädt, reisen sie fast immer als JSON (JavaScript Object Notation): reiner Text mit geschweiften Klammern und doppelten Anführungszeichen. JSON.stringify() macht aus einem Objekt Text, JSON.parse() macht aus Text wieder ein Objekt.

Shop-Daten als JSON speichern und laden

JavaScript
1
const bestellung = { nr: 10427, artikel: "Funkmaus", summeInCent: 3998 };
2
const text = JSON.stringify(bestellung);
Wandelt das Objekt in einen JSON-Text um.
3
console.log(text);
4
const geladen = JSON.parse(text);
Macht aus dem Text wieder ein nutzbares Objekt.
5
console.log("Nr:", geladen.nr, "Summe:", geladen.summeInCent);
In der Praxis

Genau so speichert auch diese Lernplattform deinen Fortschritt im localStorage des Browsers und genauso sprechen REST-APIs miteinander.

Asynchron warten mit async und await

Einen Artikelkatalog vom Server zu laden dauert Millisekunden oder Sekunden. Würde JavaScript dabei alles anhalten, fröre die ganze Webseite ein. Stattdessen liefert ein Aufruf ein Promise (Versprechen auf ein späteres Ergebnis). In einer async-Funktion pausiert await nur diese eine Funktion, während die Oberfläche bedienbar bleibt.

In der Praxis

Jeder fetch()-Aufruf im Browser nutzt async/await: Der Nutzer kann weiter scrollen, während im Hintergrund der Lagerbestand geladen wird.

Das DOM: Buttons und Warenkorb im Browser

Im Browser stellt das DOM (Document Object Model) die HTML-Seite als Baum aus Elementen dar. Mit document.querySelector() suchst du ein Element und reagierst mit addEventListener("click", ...) (einem Lambda / einer Pfeilfunktion) auf Klicks.

In der Praxis

textContent setzt reinen Text statt HTML – das schützt automatisch vor Cross-Site-Scripting (XSS), anders als innerHTML.

Typische Stolperfallen

Achtung

Nutze zum Anzeigen von Nutzereingaben im DOM immer textContent statt innerHTML, um XSS-Angriffe zu verhindern.

Prüfe dich

  1. Was bewirkt await in einer async-Funktion?
    • Nur diese Funktion wartet auf das Promise, der Rest läuft weiter
    • Der gesamte Browser friert ein, bis der Server antwortet
    • Ein Fehler im Promise wird automatisch stumm ignoriert
    • Die Funktion wird zweimal parallel gestartet
  2. Welche Methode wandelt einen JSON-Text zurück in ein JavaScript-Objekt?
    • JSON.toObject()
    • JSON.stringify()
    • Object.fromText()
    • JSON.parse()
  3. Warum ist element.textContent = eingabe sicherer als element.innerHTML = eingabe?
    • innerHTML funktioniert in modernen Browsern nicht mehr
    • textContent führt kein eingeschleustes HTML/Script aus (XSS-Schutz)
    • textContent ist die einzige Eigenschaft, die Zahlen anzeigen kann
    • textContent verschlüsselt den Text automatisch mit TLS

Exceptions: Fehler abfangen statt abstürzen

Ziel dieser Lektion

Du fängst Laufzeitfehler mit try, catch und finally ab, löst eigene Fehler mit throw new Error() aus und kennst SyntaxError, TypeError und JSON.parse-Fehler.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Fehler gehören zum Web-Alltag

In Web-Apps kommen ständig kaputte Daten an: beschädigtes JSON aus einer Schnittstelle, ein ausverkaufter Artikel oder eine ungültige Bestellmenge. Eine Exception meldet diesen Laufzeitfehler. Mit try und catch fängst du sie ab, statt die ganze Seite abstürzen zu lassen.

In der Praxis

Jeder API-Aufruf und jedes localStorage.getItem() kann beschädigtes JSON liefern. Ohne try/catch bleibt die Web-App weiß.

Die Geschäftslogik wirft eine klare Fehlermeldung, die Oberfläche fängt sie und zeigt dem Kunden einen roten Hinweis – und finally schließt den Lade-Spinner.

Typische Stolperfallen

Achtung

Nie einen leeren catch (e) {}-Block schreiben! Er verschluckt Fehler spurlos. Mindestens loggen (inkl. Stacktrace e.stack) oder dem Nutzer sauber melden.

Prüfe dich

  1. Was passiert mit den restlichen Zeilen im try-Block nach einem throw?
    • Sie werden beim nächsten Aufruf nachgeholt
    • Sie werden noch zu Ende ausgeführt, dann folgt catch
    • Sie laufen erst nach dem finally-Block
    • Sie werden übersprungen, JavaScript springt direkt ins catch
  2. Wann läuft ein finally-Block?
    • Immer – egal ob ein Fehler auftrat oder nicht
    • Nur wenn im try-Block kein Fehler passiert ist
    • Nur wenn ein Fehler im catch gefangen wurde
    • Nur bei einem SyntaxError
  3. Welchen Fehler wirft const t = null; console.log(t.titel);?
    • ReferenceError
    • TypeError
    • RangeError
    • SyntaxError

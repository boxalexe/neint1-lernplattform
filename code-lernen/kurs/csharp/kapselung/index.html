Kapselung: Properties, Lagerbestand und Passwort schützen

Ziel dieser Lektion

Du kapselst Zustände mit private Feldern und { get; private set; }, erzwingst Geschäftsregeln in Methoden wie Verkaufen() und liest Sichtbarkeiten im UML.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Kapselung in einer Zeile: { get; private set; }

In C# brauchst du für einfache Kapselung keine separaten Getter und Setter-Methoden: public int Lager { get; private set; } macht das Lesen öffentlich (+) und das Schreiben privat (-). Geschäftsregeln wie „Bestand nie negativ“ sitzen in fachlichen Methoden wie Verkaufen(int menge).

In der Praxis

Wenn ein Entwickler versucht, von außen maus.Lager = -10 zu schreiben, verhindert der C#-Compiler das sofort beim Übersetzen.

Typische Stolperfallen

Tipp

C# nennt die Paket-Sichtbarkeit (~ im UML) internal – sie gilt für das gesamte .NET-Projekt (Assembly).

Prüfe dich

  1. Was bewirkt { get; private set; } bei public int Lager?
    • Die Property wird automatisch statisch für alle Objekte
    • Ändern ist öffentlich, Lesen nur innerhalb der eigenen Klasse
    • Weder Lesen noch Ändern ist innerhalb der Klasse erlaubt
    • Lesen ist öffentlich, Ändern nur innerhalb der eigenen Klasse
  2. Welche Sichtbarkeit in C# entspricht ~ (Paket-Sichtbarkeit) im UML?
    • protected
    • static
    • private
    • internal
  3. Wann ist eine fachliche Methode Verkaufen(int menge) besser als ein öffentlicher Setter?
    • Wenn die Klasse keine Konstruktoren besitzt
    • Wenn das Attribut überhaupt nicht verändert werden darf
    • Wenn der Wert nur einmal angezeigt werden soll
    • Wenn Geschäftsregeln wie „nie unter 0“ erzwungen werden sollen

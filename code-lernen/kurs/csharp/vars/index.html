Variablen, Datentypen und Umwandlung: Preise, Mengen, Eingaben

Ziel dieser Lektion

Du wählst passende C#-Datentypen (int, long, decimal, string, bool), rechnest sicher mit Ganzzahl-Division und Modulo, nutzt $-Interpolation und wandelst Eingaben sicher mit int.TryParse um.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Feste Datentypen und exaktes Geld

Jede Variable hat in C# einen festen Datentyp. Geldbeträge speicherst du entweder als ganze Zahl in Cent (long oder int) – oder mit C#s eigenem Dezimaltyp decimal (19.99m), der im Gegensatz zu double exakt im Zehnersystem rechnet. Mit const legst du eine unveränderliche Konstante fest.

Ein Artikel in C#-Variablen

C#
1
string artikel = "Funkmaus";
Text (string klein geschrieben).
2
long preisInCent = 1999;
Ganze Zahl in Cent – exakt wie in Java und Python.
3
int menge = 2;
4
bool lieferbar = true;
Wahrheitswert: true oder false.
5
const long VersandInCent = 495;
Konstante: darf nicht mehr geändert werden.
6
menge = menge + 1;
Erst rechts rechnen, dann speichern: 3.
7
long summeInCent = preisInCent * menge;
8
Console.WriteLine($"{menge} x {artikel}: {summeInCent} Cent");
$-Interpolation setzt Variablen direkt in {} ein.
In der Praxis

$-Interpolation ist das C#-Gegenstück zu Pythons f-Strings und JavaScripts Backticks – sauber, kurz und direkt vom Compiler geprüft.

Ganzzahl-Division, Modulo, Cast und String-Vergleich

C#
1
long summeInCent = 3998;
2
long euro = summeInCent / 100;
Ganzzahl-Division: 3998 / 100 ergibt 39 (Rest abgeschnitten).
3
long cent = summeInCent % 100;
Modulo (%): Rest der Division ist 98.
4
Console.WriteLine($"{euro},{cent:D2} Euro");
D2 formatiert zweistellig (z. B. 05 statt 5).
5
double schnitt = (double)17 / 4;
Expliziter Cast auf double: 4.25 statt ganzzahlig 4.
6
bool gleich = ("admin" == "ad" + "min");
Wichtig: In C# vergleicht == bei string den INHALT (True)!
In der Praxis

Anders als in Java darfst du Strings in C# direkt mit == vergleichen – C# prüft dabei den Textinhalt, nicht die Objektadresse.

Eingaben sicher parsen mit int.TryParse

C#
1
string eingabe = "3";
Console.ReadLine() liefert immer Text (string).
2
int menge = int.Parse(eingabe);
Parsen: wirft bei "drei" eine FormatException.
3
bool ok = int.TryParse("drei", out int sicher);
TryParse stürzt nie ab: liefert false und sicher = 0.
4
Console.WriteLine($"{menge} {ok} {sicher}");
In der Praxis

int.TryParse ist die C#-Standardlösung für Benutzereingaben: keine Exception bei Tippfehlern, stattdessen ein sauberer bool.

Typische Stolperfallen

Achtung

7 / 2 ergibt bei zwei int in C# 3, nicht 3,5! Für eine Kommazahl braucht mindestens eine Seite ein (double) oder 2.0.

Prüfe dich

  1. Was ergibt 17 / 5 und 17 % 5 bei int-Zahlen in C#?
    • 3,4 und 2
    • 2 und 3
    • 3 und 0,4
    • 3 und 2
  2. Was unterscheidet int.TryParse von int.Parse bei ungültiger Eingabe "zwei"?
    • TryParse wandelt das Wort "zwei" automatisch in die Zahl 2 um
    • Parse liefert 0 ohne Absturz, TryParse wirft eine FormatException
    • TryParse liefert false ohne Absturz, Parse wirft eine FormatException
    • Beide werfen eine FormatException, TryParse ist nur kürzer
  3. Was prüft a == b bei zwei string-Variablen in C#?
    • Den Textinhalt beider Strings
    • Ausschließlich die Speicheradresse im Heap
    • Nur die Länge beider Strings
    • Es löst in C# einen Compilerfehler aus
  4. Welcher Datentyp aus der IHK-Tabelle speichert Prozentwerte (0–100) am speichersparsamsten?
    • int (32 Bit)
    • byte (8 Bit)
    • long (64 Bit)
    • double (64 Bit)

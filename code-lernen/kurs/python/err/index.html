Exceptions: Fehler abfangen statt abstürzen

Ziel dieser Lektion

Du fängst Fehler mit try und except gezielt ab, nutzt else und finally, löst eigene Exceptions mit raise aus, liest einen Traceback und weißt, warum ein leerer except-Block gefährlich ist.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Fehler gehören zum Betrieb

Kunden vertippen sich, Artikel sind ausverkauft, Dateien fehlen. Python meldet solche Laufzeitfehler mit einer Exception. Ohne Behandlung bricht das Programm ab. Mit try und except fängst du sie gezielt ab und reagierst: Hinweis anzeigen, Eingabe überspringen, Bestellung ablehnen.

In der Praxis

Jedes Importskript, das Bestellungen, Kundendaten oder Preise aus Dateien liest, braucht diesen Aufbau: fehlerhafte Zeilen melden und überspringen, statt beim ersten Tippfehler den ganzen Import abzubrechen.

Typische Stolperfallen

Achtung

Nie ein leerer except-Block. except: pass verschluckt jeden Fehler spurlos, auch Tippfehler im eigenen Code. Mindestens protokollieren, am besten gar nicht so allgemein fangen.

Achtung

So genau wie möglich fangen: except ValueError statt except Exception. Sonst behandelst du Fehler als „falsche Eingabe“, die in Wahrheit ein Programmierfehler sind.

Tipp

Dateien mit with open(…) as datei: öffnen. Der with-Block schließt die Datei auch dann, wenn eine Exception fliegt. Das ist ein eingebautes finally.

Kapselung: Lagerbestand und Passwort schützen

Ziel dieser Lektion

Du kennst die Python-Konventionen _intern und __privat, schützt Attribute mit @property und Settern, die ungültige Werte abweisen, und weißt, warum ein Passwort nie lesbar im Objekt liegt.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Niemand soll den Bestand auf −5 setzen

Bisher darf jeder Programmteil maus.lager = -5 schreiben. Kapselung heißt: Ein Objekt schützt seine Daten selbst und lässt Änderungen nur über Wege zu, die es prüft.

Python kennt kein private wie Java. Die Sichtbarkeit regelt eine Konvention: Ein Unterstrich wie in _lager heißt „intern, von außen nicht anfassen“. Zwei Unterstriche wie in __lager versteckt Python zusätzlich unter einem anderen Namen. Echten Schutz bringt eine Property: Sie sieht von außen aus wie ein Attribut, ruft aber Methoden auf, einen Getter zum Lesen und einen Setter zum Schreiben.

In der Praxis

Ein negativer Bestand fällt oft erst Wochen später auf, wenn Kunden Ware bestellen, die es nicht gibt. Je früher ein ungültiger Wert abgewiesen wird, desto billiger ist der Fehler.

Sichtbarkeit in Python

Python setzt auf Absprache statt Verbot: „We are all consenting adults here.“ Wer _lager von außen ändert, weiß, dass er eine Regel bricht.

In der Praxis

Datenbanken werden gestohlen. Steht dort nur ein Hashwert mit Salt, ist das Passwort nicht direkt lesbar. In echten Projekten übernimmt das eine geprüfte Bibliothek, nie selbst gebaute Kryptografie.

Typische Stolperfallen

Achtung

Ein Unterstrich schützt nicht, er bittet. Was wirklich nicht falsch werden darf, gehört hinter eine Property oder Methode, die prüft.

Achtung

Passwörter nie im Klartext speichern, nie in Logs schreiben, nie mit einem schnellen Hash wie SHA-256 allein. Richtig sind langsame Verfahren mit Salt (bcrypt, Argon2) aus einer geprüften Bibliothek.

Tipp

Eine Property ohne Setter ist schreibgeschützt: Lesen geht, objekt.wert = … löst einen AttributeError aus.

Prüfe dich

  1. Was bedeutet der Unterstrich in self._lager?
    • Python verbietet jeden Zugriff von außen
    • Das Attribut ist eine Klasse
    • Konvention: intern, von außen nicht anfassen
    • Das Attribut ist eine Konstante
  2. Was passiert bei maus.lager = -5, wenn ein Setter mit Prüfung existiert?
    • Der Setter läuft und weist den Wert ab
    • Der Wert wird ohne Prüfung gespeichert
    • Python ignoriert die Zuweisung still
    • Ein SyntaxError beim Start
  3. Warum speichert die Benutzer-Klasse nur einen Hashwert?
    • Weil Python keine Texte speichern kann
    • Damit der Benutzer es nicht vergisst
    • Weil Hashwerte kürzer zu tippen sind
    • Damit das Passwort selbst nirgends lesbar liegt
  4. Welche Aussage zu @property stimmt?
    • Es macht ein Attribut unsichtbar
    • Es ersetzt den Konstruktor
    • Es geht nur bei Zahlen
    • Von außen sieht es aus wie ein Attribut

Clean Code: lesbar schreiben, was andere lesen müssen

Ziel dieser Lektion

Du erkennst sprechende Namen, ersetzt magische Zahlen durch Konstanten, entflechtest verschachtelte if-Blöcke mit Guard Clauses, vermeidest Wiederholungen und kennst die wichtigsten Regeln aus PEP 8.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Code wird öfter gelesen als geschrieben

Ein Programm schreibst du einmal, gelesen wird es hundertmal: von Kollegen, beim Fehlersuchen, von dir selbst in einem halben Jahr. Clean Code heißt, so zu schreiben, dass andere es schnell verstehen und sicher ändern können. Unsauberer Code funktioniert oft trotzdem, aber jede Änderung kostet mehr Zeit. Diese Mehrkosten heißen Technische Schulden.

Für Python gibt es einen gemeinsamen Stil, PEP 8. In den Aufgaben unten tun alle Varianten dasselbe, die Ausgabe ist geprüft. Es geht nur um Lesbarkeit.

Typische Stolperfallen

Tipp

Ein guter Name macht einen Kommentar überflüssig. if warenwert_in_cent >= VERSANDFREI_AB_IN_CENT: braucht keinen Kommentar, if w >= 5000: # Versand frei schon.

Tipp

Eine Funktion, eine Aufgabe (Single Responsibility). Funktionen, die rechnen und gleichzeitig drucken, lassen sich nicht wiederverwenden.

Achtung

Clean Code heißt nicht „möglichst kurz“. Drei verschachtelte Bedingungsoperatoren in einer Zeile sind kürzer und schlechter lesbar als vier klare Zeilen.

Prüfe dich

  1. Was ist eine Magic Number?
    • Eine Zahl, die Python selbst berechnet
    • Eine Zahl ohne erklärenden Namen mitten im Code
    • Eine Zufallszahl aus random
    • Eine Konstante in Großbuchstaben
  2. Was macht eine Guard Clause?
    • Sie beendet Sonderfälle früh mit return
    • Sie fängt alle Exceptions ab
    • Sie schützt Attribute vor Zugriffen
    • Sie prüft den Code vor dem Start
  3. Wie schreibt man nach PEP 8 eine Klasse für Zahlungsarten?
    • zahlungs_methode
    • zahlungsmethode
    • ZAHLUNGSMETHODE
    • Zahlungsmethode
  4. Was bedeutet DRY?
    • Jede Regel steht nur an einer Stelle
    • Code ohne Kommentare schreiben
    • Nur trockene, also kurze Funktionen
    • Keine Schleifen verwenden

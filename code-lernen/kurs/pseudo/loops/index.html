Schleifen: Warenkorb, Login-Versuche, Ticketlisten

Ziel dieser Lektion

Du wiederholst mit FÜR eine feste Zahl von Malen, gehst mit FÜR JEDES durch eine Liste, wiederholst mit SOLANGE und WIEDERHOLE … BIS, bis eine Bedingung erfüllt ist, und erkennst Endlosschleifen und Off-by-one-Fehler.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Wiederholen statt kopieren

Ein Warenkorb hat mal zwei, mal zwanzig Artikel. Eine Schleife wiederholt denselben Block für jedes Element. Drei Arten gibt es:

  • FÜR JEDES preis IN preise: für jedes Element einer Liste
  • FÜR i VON 1 BIS 10: eine feste Anzahl, mit Zähler
  • SOLANGE bedingung: solange etwas gilt, Anzahl vorher unbekannt

Den Warenkorb summieren

Pseudocode
1
preise <- [1999, 999, 4950]
Eine Liste mit drei Preisen in Cent.
2
summe <- 0
Startwert vor der Schleife.
3
FÜR JEDES preis IN preise
preis nimmt nacheinander jeden Wert der Liste an.
4
  summe <- summe + preis
5
  AUSGABE "Zwischensumme:", summe
6
ENDE FÜR
7
AUSGABE "Warenkorb:", summe, "Cent"
Nach ENDE FÜR: läuft einmal, am Schluss.
In der Praxis

Summen, Zähler und Durchschnitte über eine Liste sind die häufigste Schleife überhaupt: Warenkorbwert, offene Tickets, Umsatz des Tages.

Drei Login-Versuche

Pseudocode
1
RICHTIG <- "geheim"
2
eingaben <- ["hallo", "Geheim", "geheim"]
Die drei Eingaben, hier vorgegeben statt eingelesen.
3
versuche <- 0
4
angemeldet <- FALSCH
5
SOLANGE versuche < 3 UND NICHT angemeldet
Kopfgesteuert: Die Bedingung wird vor jedem Durchlauf geprüft.
6
  WENN eingaben[versuche] = RICHTIG DANN
7
    angemeldet <- WAHR
8
  ENDE WENN
9
  versuche <- versuche + 1
Ohne diese Zeile wäre es eine Endlosschleife.
10
ENDE SOLANGE
11
AUSGABE "Angemeldet:", angemeldet, "nach", versuche, "Versuchen"
In der Praxis

Begrenzte Wiederholungen schützen jedes Login vor Passwort-Raten. Nach drei Fehlversuchen sperrt die Benutzerverwaltung das Konto.

Kopf- und fußgesteuert

SOLANGE prüft vor dem Durchlauf: Ist die Bedingung gleich zu Beginn falsch, läuft der Block kein einziges Mal. WIEDERHOLE … BIS bedingung ist fußgesteuert: Der Block läuft mindestens einmal, geprüft wird am Ende. Achtung, die Logik ist umgedreht: SOLANGE läuft, solange etwas gilt, BIS hört auf, sobald es gilt.

Ware verpacken mit WIEDERHOLE

Pseudocode
1
bestand <- 7
Sieben Funkmäuse auf Lager.
2
kartons <- 0
3
WIEDERHOLE
Fußgesteuert: Der Block läuft mindestens einmal.
4
  bestand <- bestand - 3
In jeden Karton passen drei.
5
  kartons <- kartons + 1
6
BIS bestand <= 0
Aufhören, sobald alles verpackt ist.
7
AUSGABE kartons, "Kartons"
In der Praxis

Fußgesteuerte Schleifen passen, wenn ein Schritt auf jeden Fall einmal passieren muss: das Menü einmal anzeigen, die erste Eingabe abfragen, den ersten Karton packen.

Typische Stolperfallen

Achtung

Endlosschleife: SOLANGE menge > 0 ohne menge <- menge - 1 im Block hört nie auf. Der Player bricht nach 3000 Schritten ab.

Achtung

Off-by-one: Listen beginnen bei Index 0, der letzte ist LÄNGE(liste) - 1. FÜR i VON 0 BIS LÄNGE(liste) greift einmal zu weit.

Prüfe dich

  1. Wie oft läuft FÜR i VON 2 BIS 6 SCHRITT 2?
    • 2-mal
    • 5-mal
    • 4-mal
    • 3-mal
  2. Welche Schleife läuft mindestens einmal?
    • FÜR … VON … BIS
    • FÜR JEDES
    • WIEDERHOLE … BIS
    • SOLANGE
  3. Was fehlt einer Endlosschleife meistens?
    • Eine AUSGABE innerhalb des Schleifenkörpers
    • Eine Änderung, die die Bedingung falsch macht
    • Ein ENDE SOLANGE am Schluss des Blocks
    • Ein Startwert für die Zählvariable davor

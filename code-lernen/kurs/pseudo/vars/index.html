Variablen und Eingabe: Preise und Mengen

Ziel dieser Lektion

Du legst Variablen mit ← an, änderst ihren Wert, liest Werte mit EINGABE ein und weißt, warum der Shop Geldbeträge in Cent speichert.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Ein Name für einen Wert

Der Shop muss sich merken, welcher Artikel im Korb liegt, was er kostet und wie oft er bestellt wird. Dafür gibt es Variablen: Namen für Werte. Die Zuweisung menge <- 2 legt den Wert 2 in die Variable menge. Der Pfeil zeigt die Richtung: Der Wert rechts wandert in den Namen links.

Rechts darf auch eine Rechnung stehen. Sie wird zuerst ausgerechnet, erst dann wird zugewiesen. Darum ist menge <- menge + 1 kein Widerspruch: Nimm den alten Wert, zähle eins dazu, speichere das Ergebnis.

Ein Artikel im Warenkorb

Pseudocode
1
artikel <- "Funkmaus"
Ein Text.
2
preisInCent <- 1999
Eine ganze Zahl. Preise in Cent, damit keine Rundungsfehler entstehen.
3
menge <- 2
4
lieferbar <- WAHR
Ein Wahrheitswert: WAHR oder FALSCH.
5
menge <- menge + 1
Erst rechts rechnen (2 + 1), dann zuweisen: menge ist jetzt 3.
6
summeInCent <- preisInCent * menge
Neue Variable aus zwei vorhandenen.
7
AUSGABE artikel, menge, "Stück:", summeInCent, "Cent"
In der Praxis

Preise in Cent als ganze Zahl sind in Shops und Kassensystemen Standard. Kommazahlen wie 19,99 kann ein Rechner nicht immer exakt speichern, bei Geld darf aber kein Cent verloren gehen.

Welche Art von Wert?

Im Pseudocode schreibst du den Datentyp nicht hin, er ergibt sich aus dem Wert. Java verlangt ihn bei jeder Variable (int menge = 2;), Python wie hier nicht.

Werte einlesen

EINGABE menge wartet auf eine Eingabe und legt sie in die Variable. Im Player fragt ein kleines Fenster nach dem Wert. Eine Konstante ist ein Wert, der sich nicht ändern soll, etwa der Versandpreis. Man schreibt sie üblicherweise in Großbuchstaben: VERSAND_IN_CENT <- 495.

Die Menge einlesen

Pseudocode
1
VERSAND_IN_CENT <- 495
Konstante: Großbuchstaben als Zeichen „nicht ändern“.
2
EINGABE menge
Der Kunde gibt die Menge ein, zum Beispiel 3.
3
preisInCent <- 1999
4
gesamt <- preisInCent * menge + VERSAND_IN_CENT
Punkt vor Strich: erst multiplizieren, dann den Versand addieren.
5
AUSGABE "Zu zahlen:", gesamt, "Cent"
In der Praxis

Das Mengenfeld im Bestellformular ist genau so eine Eingabe. Im echten Programm muss danach geprüft werden, ob wirklich eine sinnvolle Zahl angekommen ist. Das kommt in den Modulen zu Entscheidungen und Fehlern.

Dasselbe in Java und Python

Achtung: Java und Python schreiben die Zuweisung mit einem einfachen =. Gemeint ist dasselbe wie der Pfeil. Weiter in Java, Modul 2 und Python, Modul 2.

Typische Stolperfallen

Tipp

Sprechende Namen mit Einheit: preisInCent statt p. In einem halben Jahr weißt du sonst nicht mehr, ob Euro oder Cent gemeint war.

Achtung

Eine Variable muss einen Wert haben, bevor sie gelesen wird. AUSGABE summe ohne vorheriges summe <- … ist ein Fehler.

Prüfe dich

  1. Welchen Wert hat menge nach menge <- 2 und menge <- menge * 3?
    • 5
    • 2
    • 3
    • 6
  2. Was bedeutet der Pfeil in summe <- preis * menge?
    • preis wird in summe umbenannt
    • Die Zeile wird später ausgeführt
    • summe und preis * menge werden verglichen
    • Das Ergebnis rechts kommt in die Variable links
  3. Warum rechnet der Shop mit Cent statt mit Euro?
    • Ganze Zahlen sind exakt, Kommazahlen nicht immer
    • Pseudocode kennt überhaupt keine Kommazahlen
    • Euro-Beträge dürfen gesetzlich nicht gespeichert werden
    • Cent-Beträge sind kürzer und schneller zu tippen

Klassische Algorithmen

Ziel dieser Lektion

Du kennst Suchen, Sortieren und Rekursion und kannst sie im Ablauf nachvollziehen.

Der Stoff

Lineare Suche

Du willst wissen, ob ein Wert in einer Liste steckt. Der einfachste Weg: Geh die Liste von vorn nach hinten durch und vergleiche jedes Element. Bei einem Treffer kannst du sofort aufhören.

Eine Position suchen

Pseudocode
1
gesucht <- 7
Der Wert, den wir finden wollen.
2
zahlen <- [4, 9, 7, 1]
Die Liste, in der wir suchen.
3
position <- -1
-1 bedeutet „nicht gefunden“, ein Wert, der als Index nicht vorkommen kann.
4
FÜR i VON 0 BIS LÄNGE(zahlen) - 1
Geht alle gültigen Indizes durch: 0 bis Länge minus 1.
5
  WENN zahlen[i] = gesucht DANN
Vergleicht das aktuelle Element mit dem gesuchten Wert.
6
    position <- i
Merkt sich, an welcher Stelle der Treffer liegt.
7
  ENDE WENN
8
ENDE FÜR
9
AUSGABE "Gefunden an Position", position
Gibt 2 aus (der dritte Eintrag, Zählung ab 0).

Sortieren mit Bubble Sort

Beim Bubble Sort vergleichst du immer zwei Nachbarn und tauschst sie, wenn sie in der falschen Reihenfolge stehen. Nach jeder Runde ist das größte Element ganz hinten „aufgestiegen“ wie eine Blase. Nach genug Runden ist alles sortiert. Das Tauschen braucht, wie bei den Variablen, eine Hilfsvariable.

Bubble Sort

Pseudocode
1
zahlen <- [5, 2, 9, 1]
Die unsortierte Liste.
2
n <- LÄNGE(zahlen)
Anzahl der Elemente.
3
FÜR runde VON 1 BIS n - 1
Es genügen n−1 Runden.
4
  FÜR i VON 0 BIS n - 2
Vergleicht in jeder Runde alle Nachbarpaare (i und i+1).
5
    WENN zahlen[i] > zahlen[i + 1] DANN
Steht das linke Element vor einem kleineren?
6
      tmp <- zahlen[i]
Hilfsvariable: merkt sich das linke Element.
7
      zahlen[i] <- zahlen[i + 1]
Das rechte Element rückt nach links.
8
      zahlen[i + 1] <- tmp
Das gemerkte Element kommt nach rechts. Getauscht!
9
    ENDE WENN
10
  ENDE FÜR
11
ENDE FÜR
12
AUSGABE zahlen
Gibt die sortierte Liste aus: [1, 2, 5, 9].

Rekursion: eine Funktion ruft sich selbst auf

Manche Probleme lösen sich elegant, wenn eine Funktion sich selbst mit einem kleineren Problem aufruft, bis ein einfacher Fall erreicht ist. Das Schulbeispiel ist die Fakultät: 5! = 5 * 4 * 3 * 2 * 1 = 5 * 4!. Wichtig ist immer eine Abbruchbedingung, sonst ruft sich die Funktion ewig selbst auf.

Fakultät rekursiv

Pseudocode
1
FUNKTION fakultaet(n)
Berechnet n! = n * (n-1) * … * 1.
2
  WENN n <= 1 DANN
Abbruchbedingung: der einfachste Fall. 1! ist 1.
3
    GIB ZURÜCK 1
Ohne diese Zeilen gäbe es nie ein Ende.
4
  ENDE WENN
5
  GIB ZURÜCK n * fakultaet(n - 1)
Der rekursive Aufruf mit einem kleineren Wert: n! = n * (n−1)!
6
ENDE FUNKTION
7
AUSGABE fakultaet(4)
Gibt 24 aus. Verfolge den Ablauf und beobachte, wie rechts mehrere Funktionsaufrufe übereinander liegen.

Typische Stolperfallen

Tipp

Rekursion fühlt sich am Anfang seltsam an. Das ist normal. Der Ablauf-Player zeigt dir bei jedem Aufruf einen eigenen Kasten mit den Variablen dieses Aufrufs. So siehst du, wie die Aufrufe sich stapeln und wieder auflösen.

Prüfe dich

  1. Wozu braucht Bubble Sort beim Tauschen eine Hilfsvariable?
    • Damit sich der Index nach jedem Tausch erhöht
    • Weil Listen in einer Schleife nicht verändert werden dürfen
    • Damit der Algorithmus weniger Durchläufe braucht
    • Damit beim Überschreiben ein Wert nicht verloren geht
  2. Was darf bei einer rekursiven Funktion nie fehlen?
    • Eine Abbruchbedingung
    • Ein Rückgabewert vom Typ Liste
    • Eine globale Zählvariable
    • Eine äußere Schleife

Schreibtischtest und Fehlersuche

Ziel dieser Lektion

Du zerlegst eine Aufgabe in Schritte, prüfst einen Ablauf mit dem Schreibtischtest Zeile für Zeile, findest Fehler in fremdem Pseudocode und ordnest sie als Syntax-, Laufzeit- oder Logikfehler ein.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Von der Aufgabe zum Ablauf

Vor jeder Aufgabe hilft diese Reihenfolge:

  1. Verstehen: Was ist gegeben, was soll herauskommen?
  2. Von Hand lösen: mit kleinen, konkreten Zahlen. Achte darauf, was du dabei tust.
  3. Zerlegen: Jeder Handgriff wird ein Schritt im Pseudocode.
  4. Prüfen: mit einem Schreibtischtest.

Beim Schreibtischtest spielst du den Computer. Du gehst den Ablauf Zeile für Zeile durch und notierst nach jedem Schritt die Werte der Variablen in einer Tabelle. So findest du Fehler, bevor eine Zeile echter Code existiert. In der Prüfung ist er eine feste Aufgabenform.

Vom Text zum Pseudocode

Pseudocode
1
// Aufgabe: Durchschnitt der Bewertungen eines Artikels
Schritt 1: verstehen. Gegeben sind Sterne, gesucht ist der Durchschnitt.
2
sterne <- [5, 4, 4, 3]
Schritt 2, von Hand: 5 + 4 + 4 + 3 = 16, geteilt durch 4 ergibt 4.
3
summe <- 0
Schritt 3, zerlegen: erst summieren …
4
FÜR JEDES s IN sterne
5
  summe <- summe + s
6
ENDE FÜR
7
schnitt <- summe / LÄNGE(sterne)
… dann durch die Anzahl teilen.
8
AUSGABE "Bewertung:", schnitt, "Sterne"
Schritt 4: prüfen. Kommt dasselbe heraus wie von Hand?
In der Praxis

Die Sternebewertung unter jedem Artikel entsteht genau so. Wer vorher von Hand mit vier Werten rechnet, merkt sofort, wenn das Programm später etwas anderes liefert.

Die drei Fehlerarten

Logikfehler sind die teuersten: Niemand meldet sie. Gegen sie hilft nur der Schreibtischtest mit einem Ergebnis, das du vorher von Hand ausgerechnet hast.

FehlerartWann merkt man es?Typisch im Pseudocode
Syntaxfehlersofort: Der Ablauf startet nichtfehlendes ENDE WENN, offenes Anführungszeichen, = statt <- bei der Zuweisung
Laufzeitfehlerbeim Ablauf: Er bricht an einer Stelle abIndex außerhalb der Liste, Variable ohne Wert, Division durch 0, Endlosschleife
Logikfehlergar nicht von selbst: Es läuft und liefert Falschesfalsche Grenze, falscher Startwert, Klammer vergessen, UND statt ODER

So gehst du bei der Fehlersuche vor

Fehler suchen und beheben heißt Debugging.

  1. Wo? Welche Zeile verursacht den Fehler? Das ist nicht immer die Zeile, in der es knallt. Bei einem Index-Fehler im Schleifenkörper sitzt die Ursache oft im Schleifenkopf.
  2. Was für ein Fehler? Syntax, Laufzeit oder Logik.
  3. Wie korrigieren? Die kleinste Änderung, die die Ursache behebt.

In den Aufgaben unten wählst du Zeile, Fehlerart und Korrektur. Jede Aufgabe ist mit dem Interpreter geprüft: Der Fehler tritt genau so auf, und genau eine Korrektur liefert das richtige Ergebnis.

Typische Stolperfallen

Tipp

Im Schreibtischtest eine Spalte pro Variable und eine Zeile pro Schritt. Bei Schleifen reicht oft eine Zeile pro Durchlauf, aber dann konsequent immer an derselben Stelle.

Achtung

Behebe die Ursache, nicht das Symptom. Wer bei einem Index-Fehler einfach eine Abfrage um die abstürzende Zeile baut, versteckt den Off-by-one-Fehler im Schleifenkopf nur.

Prüfe dich

  1. Der Ablauf läuft ohne Abbruch, zeigt aber eine falsche Summe. Welche Fehlerart?
    • Logikfehler
    • Laufzeitfehler
    • Gar kein Fehler
    • Syntaxfehler
  2. Wozu dient ein Schreibtischtest?
    • Pseudocode in Maschinencode übersetzen
    • Einen Ablauf von Hand durchspielen und Fehler finden
    • Prüfen, ob der Code auf jedem Rechner startet
    • Den Algorithmus schneller machen
  3. Im Schleifenkörper kommt „Index 3 gibt es nicht“. Wo liegt die Ursache meistens?
    • In der AUSGABE nach der Schleife
    • Im Namen der Liste
    • In der ersten Zeile des Algorithmus
    • Im Schleifenkopf, bei der oberen Grenze

Übungen

  1. Schreibtischtest: Der Durchschnitt der Bewertungen. Trage s und summe nach jedem Durchlauf ein.

    Pseudocode
    1
    sterne <- [5, 4, 4, 3]
    2
    summe <- 0
    3
    FÜR JEDES s IN sterne
    4
      summe <- summe + s
    5
    ENDE FÜR
    6
    AUSGABE summe / LÄNGE(sterne)
    Durchlaufssumme

  2. Schreibtischtest: Zwei Variablen hängen voneinander ab. Trage a und b nach jedem Durchlauf ein.

    Pseudocode
    1
    a <- 2
    2
    b <- 3
    3
    FÜR i VON 1 BIS 3
    4
      a <- a + b
    5
      b <- a - b
    6
      AUSGABE a, b
    7
    ENDE FÜR
    Durchlaufiab

  3. Ticketsystem: Der Ablauf startet nicht, der Player meldet einen Fehler.

    Pseudocode
    1
    offen <- 3
    2
    WENN offen = 0 DANN
    3
      AUSGABE "Alles erledigt"
    4
    SONST
    5
      AUSGABE offen, "Tickets offen"

  4. Warenkorb: Der Ablauf bricht beim Summieren mit „Index 3 gibt es nicht“ ab. Finde die Zeile, die den Fehler verursacht.

    Pseudocode
    1
    preise <- [1999, 4950, 999]
    2
    summe <- 0
    3
    i <- 0
    4
    SOLANGE i <= LÄNGE(preise)
    5
      summe <- summe + preise[i]
    6
      i <- i + 1
    7
    ENDE SOLANGE
    8
    AUSGABE "Summe:", summe

  5. Shop: Der günstigste Artikel soll ermittelt werden, der Ablauf meldet 0.

    Pseudocode
    1
    preise <- [1999, 999, 4950]
    2
    guenstigster <- 0
    3
    FÜR JEDES p IN preise
    4
      WENN p < guenstigster DANN
    5
        guenstigster <- p
    6
      ENDE WENN
    7
    ENDE FÜR
    8
    AUSGABE "Günstigster:", guenstigster

  6. Lager: Gezählt werden sollen alle Artikel, die nachbestellt werden müssen (Bestand unter 10). Gemeldet wird einer zu viel.

    Pseudocode
    1
    bestand <- [120, 0, 14, 9, 10]
    2
    nachbestellen <- 0
    3
    FÜR JEDES b IN bestand
    4
      WENN b <= 10 DANN
    5
        nachbestellen <- nachbestellen + 1
    6
      ENDE WENN
    7
    ENDE FÜR
    8
    AUSGABE nachbestellen

  7. Rabattaktion: 10 % gibt es für Stammkunden oder ab 100 Euro Warenwert. Ein Stammkunde mit 30 Euro bekommt keinen Rabatt.

    Pseudocode
    1
    stammkunde <- WAHR
    2
    warenwert <- 3000
    3
    WENN stammkunde UND warenwert >= 10000 DANN
    4
      rabatt <- warenwert * 10 DIV 100
    5
    SONST
    6
      rabatt <- 0
    7
    ENDE WENN
    8

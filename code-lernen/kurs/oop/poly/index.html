Polymorphie, abstrakte Klassen und Schnittstellen

Ziel dieser Lektion

Du verstehst, warum man mit der Oberklasse arbeitet, und kennst den Unterschied zwischen abstrakter Klasse und Schnittstelle.

Der Stoff

Eine Anweisung, viele Verhaltensweisen

Du hast eine Liste mit Tieren (Hund, Katze, Ente). Für jedes soll laut() aufgerufen werden. Der Code schreibt nur: tier.laut(). Welcher Laut erklingt, entscheidet das tatsächliche Objekt. Genau das ist Polymorphie (Vielgestaltigkeit). Der Aufrufer muss nicht wissen, welche konkrete Klasse dahintersteckt.

Abstrakte Klasse

Manchmal gibt es von einer Oberklasse keine sinnvollen eigenen Objekte. Ein „allgemeines Tier“ existiert in der Natur nicht, nur Hunde, Katzen oder Enten. Dann macht man die Klasse abstrakt: Man kann kein Objekt direkt daraus erzeugen, sie dient als Vorlage. Abstrakte Klassen und Methoden stehen im UML kursiv. Eine abstrakte Methode hat keinen Inhalt, jede Unterklasse muss sie selbst ausfüllen.

Beispiel: Formen

Form ist kursiv geschrieben, also abstrakt. Jede Unterklasse berechnet flaeche() auf ihre Art (π·r² bzw. Breite·Höhe).

Schnittstelle (Interface)

Eine Schnittstelle legt nur fest, welche Methoden eine Klasse anbieten muss, ohne zu sagen, wie. Mehrere ganz verschiedene Klassen können dieselbe Schnittstelle umsetzen. Eine Schnittstelle zeichnet man mit «interface», die Umsetzung mit gestrichelter Linie und hohler Spitze.

Beispiel: Zahlungsarten

Der Warenkorb kennt nur die Schnittstelle Zahlungsart. Kommt später eine neue Zahlungsart hinzu, muss man am Warenkorb nichts ändern. Das ist der große Vorteil.

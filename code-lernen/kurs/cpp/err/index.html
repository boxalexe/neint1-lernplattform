Fehler verstehen und behandeln

Ziel dieser Lektion

Du erkennst, welche Arten von Fehlern es gibt, liest Fehlermeldungen richtig und kannst Ausnahmen abfangen.

Die Idee dahinter

Drei Sorten Fehler

  • Syntaxfehler: Du hast gegen die Schreibregeln verstoßen (Klammer vergessen). Das Programm startet gar nicht, die Meldung nennt meist die Zeile.
  • Laufzeitfehler: Das Programm startet, aber bei einer Anweisung geht etwas schief (Division durch 0, Liste zu kurz, Datei fehlt). Es bricht mit einer Fehlermeldung ab.
  • Logikfehler: Das Programm läuft ohne Meldung, liefert aber ein falsches Ergebnis (z. B. < statt <=). Diese sind am schwersten zu finden.

Fehlermeldungen lesen

Lies eine Fehlermeldung von oben nach unten und in Ruhe. Sie nennt fast immer was schiefging und wo (Zeile). Das Suchen im Programm geht dann viel schneller. Ein bewährter Trick gegen Logikfehler: Gib Zwischenwerte aus oder gehe das Programm wie im Ablauf-Player Schritt für Schritt durch.

Ausnahmen abfangen

Manche Fehler lassen sich nicht vermeiden (Benutzer tippt „abc“ statt einer Zahl, Datei fehlt). Dafür gibt es Ausnahmebehandlung: Du sagst „versuche das (try), und falls ein Fehler auftritt (catch/except), mache stattdessen jenes“. So stürzt das Programm nicht ab, sondern reagiert vernünftig.

Typische Stolperfallen

Achtung

Fange Ausnahmen gezielt ab. Ein „alles abfangen und nichts tun“ versteckt Fehler, statt sie zu lösen. Du findest sie dann nie wieder.

Tipp

Teste dein Programm bewusst mit gemeinen Eingaben: leer, 0, negative Zahlen, sehr lange Texte. Dort verstecken sich die meisten Fehler.

Gut zu wissen

Mit throw runtime_error("…"); löst du selbst einen Fehler aus. Anders als in Java gibt es keine Pflicht, Fehler zu fangen.

Prüfe dich

  1. Dein Programm läuft ohne Meldung, rechnet aber falsch. Welche Fehlerart ist das?
    • Syntaxfehler
    • Logikfehler
    • Laufzeitfehler
    • Kompilierfehler
  2. Wozu dient try … catch (bzw. try … except)?
    • Um eine Schleife bei einem Fehler zu wiederholen
    • Um Fehler abzufangen, ohne dass das Programm abstürzt
    • Um Syntaxfehler schon beim Übersetzen zu finden
    • Um Code nur beim ersten Start auszuführen
  3. Welches Schlüsselwort löst absichtlich eine Ausnahme aus?
    • raise
    • catch
    • try
    • throw

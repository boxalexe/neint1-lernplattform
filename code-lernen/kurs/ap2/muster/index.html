Entwurfsmuster: Singleton, Observer, MVC

Ziel dieser Lektion

Du kannst die drei prüfungsrelevanten Entwurfsmuster erklären, im Code erkennen und sagen, welches Problem sie lösen.

Der Stoff

Was ist ein Entwurfsmuster?

Ein Entwurfsmuster (Design Pattern) ist eine bewährte Lösung für ein Problem, das beim Programmieren immer wieder auftaucht. Es ist kein fertiger Code, sondern eher ein Bauplan-Tipp, so wie Architekten nicht jedes Treppenhaus neu erfinden. Für die Prüfung sind vor allem drei wichtig.

Singleton: Es gibt nur einen

Manche Dinge darf es nur einmal geben: eine Verbindung zur Datenbank, die Einstellungen eines Programms, das Protokoll. Ein Schiff hat genau einen Kapitän. Das Singleton sorgt dafür: Der Konstruktor ist privat, niemand kann von außen new aufrufen. Stattdessen gibt eine statische Methode immer dasselbe Objekt heraus und erzeugt es nur beim ersten Mal.

Singleton im Klassendiagramm

Typisch: privater Konstruktor (-) und eine öffentliche Methode, die das eine Objekt liefert. Statische Elemente werden in UML eigentlich unterstrichen.

Observer: Abonnieren statt Nachfragen

Stell dir einen YouTube-Kanal vor. Die Zuschauer fragen nicht jede Minute nach, ob es ein neues Video gibt. Sie abonnieren den Kanal, und der Kanal benachrichtigt alle Abonnenten, sobald etwas passiert. Das ist das Observer-Muster (Beobachter): Ein Subjekt führt eine Liste von Beobachtern und ruft bei jeder Änderung deren Methode auf. Das Subjekt muss die Beobachter nicht im Einzelnen kennen, nur ihre gemeinsame Schnittstelle.

Observer im Klassendiagramm

Der Kanal kennt nur die Schnittstelle Abonnent. Ob ein Zuschauer oder ein Mailversand dahintersteckt, ist ihm egal. Neue Abonnenten-Arten kommen dazu, ohne den Kanal zu ändern.

MVC: Model, View, Controller

Ein Restaurant hat drei Bereiche, die sich nicht in die Quere kommen: Die Küche hat die Zutaten und kocht (das Model, die Daten und Regeln). Der Teller zeigt, was gekocht wurde, schön angerichtet (die View, die Anzeige). Der Kellner nimmt Bestellungen an, gibt sie an die Küche weiter und bringt den Teller (der Controller, die Steuerung). Weil die Teile getrennt sind, kann man die Anzeige austauschen, zum Beispiel eine App statt einer Webseite, ohne die Küche umzubauen.

Ein Klick durch MVC

Prüfe dich

  1. Welches Problem löst das Singleton-Muster?
    • Es erzeugt Objekte, ohne dass der Aufrufer die Klasse kennt
    • Es trennt Daten, Anzeige und Steuerung in drei eigene Teile
    • Es stellt sicher, dass es von einer Klasse höchstens ein Objekt gibt
    • Es benachrichtigt alle angemeldeten Objekte, sobald sich etwas ändert
  2. Woran erkennst du ein Singleton im Code?
    • Drei getrennte Pakete mit den Namen Model, View und Controller
    • Privater Konstruktor und eine statische Methode, die das Objekt liefert
    • Eine abstrakte Klasse, von der genau eine Unterklasse erbt
    • Öffentlicher Konstruktor und eine Liste, in der sich Beobachter anmelden
  3. Im MVC-Muster: Welcher Teil enthält die Daten und die Geschäftsregeln?

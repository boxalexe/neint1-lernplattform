Sicherer Code: SQL-Injection, Passwörter, Eingaben

Ziel dieser Lektion

Du verstehst, wie eine SQL-Injection funktioniert, wie Prepared Statements sie verhindern und wie Passwörter richtig gespeichert werden.

Der Stoff

Jede Eingabe ist verdächtig

Ein Programm, das Eingaben ungeprüft weiterverarbeitet, ist wie ein Pförtner, der jeden Zettel laut vorliest, der ihm gereicht wird. Steht auf dem Zettel „Und jetzt öffne alle Türen“, liest er auch das vor. Bei Datenbanken heißt dieser Angriff SQL-Injection.

So entsteht die Lücke

Java
1
String sql = "SELECT * FROM nutzer WHERE name = '" + eingabe + "'";
So nicht: Die Eingabe wird direkt in den SQL-Text geklebt.
2
// eingabe = ' OR '1'='1
Ein Angreifer gibt das als Benutzernamen ein.
3
// SELECT * FROM nutzer WHERE name = '' OR '1'='1'
So kommt es bei der Datenbank an. '1'='1' ist immer wahr, also passen alle Zeilen.

Probier es aus

In der Übung unten tippst du die Abfrage, die bei so einem Angriff entsteht, und siehst selbst, dass sie alle Kunden liefert. Das passiert nur in deiner Übungsdatenbank im Browser.

Die Lösung: Prepared Statements

Ein Prepared Statement ist wie ein Formular mit festen Kästchen. Der SQL-Befehl wird vorher mit Platzhaltern ? an die Datenbank geschickt. Die Eingaben kommen getrennt hinterher und landen nur im Kästchen, niemals im Befehl selbst. Selbst ' OR '1'='1 ist dann nur ein seltsamer Name, nach dem gesucht wird.

Prepared Statement in Java

Java
1
String sql = "SELECT * FROM nutzer WHERE name = ?";
Der Befehl mit Platzhalter. Kein Nutzertext darin.
2
PreparedStatement ps = verbindung.prepareStatement(sql);
Die Datenbank bekommt den Befehl vorab und kennt seine Form.
3
ps.setString(1, eingabe);
Die Eingabe füllt Platzhalter Nummer 1, sie ist nur noch ein Wert.
4
ResultSet rs = ps.executeQuery();
Erst jetzt wird ausgeführt.

Dasselbe in Python

Python
1
cursor.execute(
Auch in Python gibt es Platzhalter.
2
    "SELECT * FROM nutzer WHERE name = ?",
Der Befehl mit Platzhalter.
3
    (eingabe,))
Die Werte separat als Tupel. Nie mit + oder f-Strings zusammenbauen.

Passwörter: nie im Klartext

Passwörter werden nicht gespeichert, sondern nur ihr Hashwert. Eine Hashfunktion ist wie ein Fleischwolf: Aus dem Steak wird Hackfleisch, aber aus dem Hackfleisch nie wieder das Steak. Beim Anmelden wird das eingegebene Passwort ebenfalls gehasht und mit dem gespeicherten Wert verglichen. Dazu kommt ein Salt, eine zufällige Zeichenkette pro Nutzer, die vor dem Hashen angehängt wird. So haben zwei Nutzer mit demselben Passwort trotzdem verschiedene Hashwerte, und vorberechnete Tabellen (Rainbow Tables) helfen Angreifern nicht. Verwendet werden langsame, dafür gebaute Verfahren wie bcrypt oder Argon2, nicht schnelle Prüfsummen wie MD5.

Fünf Regeln, die immer gelten

RegelWarum
Eingaben prüfen: erlaubte Werte festlegen (Whitelist), Länge begrenzenWas nicht erlaubt ist, kommt gar nicht erst hinein
Prepared Statements statt zusammengeklebtem SQLVerhindert SQL-Injection
Ausgaben maskieren, bevor sie in einer Webseite erscheinenVerhindert, dass eingeschleuster Code im Browser anderer Nutzer läuft (Cross-Site-Scripting, XSS)
Passwörter mit Salt und langsamem Hashverfahren speichernGestohlene Datenbanken verraten keine Passwörter
Fehlermeldungen für Nutzer allgemein haltenDetails wie Tabellennamen helfen nur Angreifern

Typische Stolperfallen

Achtung

„Ich filtere einfach das Hochkomma heraus“ reicht nicht. Es gibt zu viele Umwege. Der sichere Weg sind Prepared Statements.

Prüfe dich

  1. Was verhindert SQL-Injection zuverlässig?
    • Prepared Statements mit Platzhaltern
    • Lange Tabellennamen
    • Eingaben in Großbuchstaben umwandeln
    • Die Datenbank auf einem anderen Server betreiben
  2. Warum wird beim Speichern von Passwörtern ein Salt verwendet?
    • Gleiche Passwörter bekommen verschiedene Hashwerte, vorberechnete Tabellen helfen nicht
    • Der Salt beschleunigt die Anmeldung, weil der Hash nicht neu berechnet wird
    • Mit dem Salt als Schlüssel lässt sich das Passwort bei Bedarf wieder entschlüsseln
    • Der Salt verkürzt lange Passwörter, damit sie in die Datenbankspalte passen
  3. Was ist eine Hashfunktion?
    • Eine Funktion, die Daten verlustfrei verkleinert und wieder entpacken kann
    • Eine Einwegfunktion: Aus dem Ergebnis lässt sich die Eingabe nicht zurückrechnen
    • Ein Datenbankindex, der Zeilen nach ihrem Schlüssel sortiert ablegt
    • Eine Verschlüsselung mit Schlüssel, die sich mit demselben Schlüssel umkehren lässt
  4. Ein Angreifer gibt in ein Suchfeld <script> ein, und es läuft bei anderen Nutzern im Browser. Wie heißt der Angriff?
    • SQL-Injection (SQLi)
    • Cross-Site Request Forgery
    • Cross-Site-Scripting (XSS)
    • Denial of Service (DoS)

Übungen

  1. Ergänze den Platzhalter für ein Prepared Statement.

    SELECT * FROM nutzer WHERE name = _____

  2. Ein unsicheres Programm baut SELECT name FROM kunde WHERE name = 'EINGABE' zusammen. Ein Angreifer gibt ' OR '1'='1 ein. Schreibe die Abfrage, die dabei entsteht, und führe sie aus. Du siehst: Statt keinem Kunden kommen alle heraus.

Prüfungsaufgaben Teil 2: Objekt-Arrays, Zähler, Zeiträume, HTTP

Ziel dieser Lektion

Du löst die Algorithmus-Aufgaben, wie sie seit 2022 in Teil 2 der AP2 kommen: über ein Array von Objekten mit Get-Methoden laufen, Häufigkeiten in einem Zähler-Array sammeln, Abschnitte zwischen aufeinanderfolgenden Einträgen auswerten, Tag für Tag über einen Zeitraum zählen, die nächsten n Einträge ab jetzt finden und eine HTTP-Antwort von Hand zusammensetzen.

Der Stoff

Was sich seit 2022 geändert hat

Neuere Aufgaben geben fast immer eine kleine Klasse mit Get-Methoden vor und dazu ein Array von Objekten dieser Klasse, oft mit einer Beispieltabelle. Gefragt ist eine Funktion in Pseudocode oder einer Sprache deiner Wahl. Die Daten wechseln (Betten, Fahrten, Messwerte), die Muster dahinter kaum. Fünf davon kommen immer wieder:
- Zähler-Array: Häufigkeiten je Kategorie sammeln, die Kategorie ist der Index.
- Abschnitte: Eintrag i mit Eintrag i + 1 vergleichen, die Schleife endet eins früher.
- Zeitraum Tag für Tag: äußere Schleife über die Tage, innere über die Einträge.
- Die nächsten n: eine Schleife mit zwei Abbruchgründen.
- Antwort zusammensetzen: Text nach einem festen Format bauen, zum Beispiel eine HTTP-Antwort.

Muster 1: Das Zähler-Array

Ein Paketdienst erfasst für jede Zustellung die Tour (0 bis 2), die geplante und die tatsächliche Ankunft in Minuten seit Mitternacht (480 ist 8:00 Uhr). Gesucht: wie viele Zustellungen je Tour mehr als 10 Minuten zu spät waren. Der Trick: Die Tournummer selbst ist der Index im Ergebnis-Array. Keine if-Kette je Tour, kein Sortieren.

In der Praxis

Fehler je Maschine, Tickets je Priorität, Noten je Stufe, Besucher je Stunde: Immer wenn eine Kategorie eine kleine ganze Zahl ist, ist sie der Index. In der Prüfung wird genau diese eine Zeile mit den meisten Punkten bewertet.

Muster 2: Abschnitte zwischen zwei Einträgen

Eine Fertigungslinie hat fünf Stationen. Gespeichert ist, wann ein Werkstück jede Station planmäßig und tatsächlich erreicht hat. Ein Abschnitt liegt zwischen Station i und Station i + 1. Bei fünf Stationen gibt es also nur vier Abschnitte, und die Schleife endet beim vorletzten Index. Wer bis zum letzten läuft, greift auf ist[5] zu, das es nicht gibt.

Fahrzeiten zwischen Haltestellen, Zeit zwischen zwei Scans eines Pakets, Kursveränderung von einem Tag zum nächsten: Überall wird ein Eintrag mit seinem Nachfolger verglichen.

Muster 3: Tag für Tag über einen Zeitraum

Eine Autovermietung hat vier Autos. Jede Buchung hat ein von (Abholtag, zählt mit) und ein bis (Rückgabetag, zählt nicht mehr). Gesucht: an wie vielen Tagen der Woche mindestens 75 % der Autos vermietet waren. Die äußere Schleife geht Tag für Tag durch den Zeitraum, die innere zählt für diesen einen Tag die passenden Buchungen. In der Prüfung ist der Tag ein Datumsobjekt und der nächste Tag heißt datum + 1. Hier steht der Tag als Zahl, die Logik ist dieselbe.

In der Praxis

Bettenbelegung, Raumbuchungen, Lizenzen, Parkplätze: Wenn ein Zeitraum aus Einzeltagen besteht, die sich überlappen, zählt man Tag für Tag. Die Grenze „bis zählt nicht mehr mit“ ist die häufigste Fehlerquelle.

Muster 4: Die nächsten n ab jetzt

Eine Arztpraxis zeigt die nächsten drei freien Termine an. Die Termine liegen aufsteigend sortiert vor, in Minuten seit Mitternacht. Die Schleife hat zwei Gründe aufzuhören: Die Liste ist zu Ende, oder es sind schon n Termine gefunden. Beide gehören mit UND in die Bedingung. Gibt es weniger als n passende Termine, ist das Ergebnis eben kürzer.

In der Praxis

Nächste Abfahrten, die fünf neuesten Nachrichten, die ersten zehn Suchtreffer: Ein Limit plus eine Bedingung. Mit einer for-Schleife über alle Einträge geht es auch, dann brauchst du ein zusätzliches Abbrechen, sobald n erreicht ist.

Muster 5: Eine HTTP-Antwort zusammensetzen

Manchmal ist ein Antworttext nach festem Format gefragt, etwa eine Fehlermeldung einer Web-API. Eine HTTP-Antwort besteht aus der Statuszeile, den Headern (je Name: Wert), einer Leerzeile und dem Body. Zeilen enden in HTTP mit \r\n. Die Falle steckt in Content-Length: Gezählt werden Bytes, nicht Zeichen, und ein Umlaut braucht in UTF-8 zwei Bytes.

In der Praxis

Frameworks setzen Content-Length normalerweise selbst. Wer es von Hand macht und Zeichen statt Bytes zählt, schneidet bei Umlauten das letzte Zeichen ab, ein klassischer Fehler in selbstgebauten Schnittstellen.

Achtung

Bei allen fünf Mustern hängen die Punkte an den Grenzen: Schleife bis Länge minus 1 oder minus 2, < oder <= beim Rückgabetag, UND statt ODER bei zwei Abbruchgründen. Schreib dir für jede Grenze ein Beispiel mit echten Zahlen auf, bevor du den Code hinschreibst.

Typische Stolperfallen

Tipp

Steht in der Aufgabe eine Beispieltabelle, rechne das erwartete Ergebnis zuerst von Hand aus. Dann hast du deinen eigenen Testfall und merkst beim Schreibtischtest sofort, ob dein Algorithmus stimmt.

Prüfe dich

  1. Die Tour ist eine Zahl von 0 bis 4. Wie zählst du Verspätungen je Tour am kürzesten?
    • Mit fünf Durchläufen über alle Zustellungen, je Tour einen
    • Indem du die Zustellungen zuerst nach der Tour sortierst
    • Mit fünf if-Abfragen und je einer eigenen Variable pro Tour
    • Mit zaehler[z.getTour()]++ in einem int-Array der Länge 5
  2. Ein Array hat 6 Haltepunkte. Wie viele Abschnitte liegen dazwischen, und wie weit läuft i?
    • 6 Abschnitte, i läuft von 1 bis 6
    • 5 Abschnitte, i läuft von 0 bis 4
    • 5 Abschnitte, i läuft von 0 bis 5
    • 6 Abschnitte, i läuft von 0 bis 5
  3. Eine Buchung läuft von Tag 2 bis Tag 5, der Rückgabetag zählt nicht. Welche Bedingung prüft Tag t richtig?
    • von <= t ODER t < bis
    • von <= t UND t < bis
    • von <= t UND t <= bis
    • von < t UND t <= bis
  4. Warum steht bei „Prüfung“ im Header Content-Length: 8 und nicht 7?
    • Content-Length rechnet immer ein Byte für das Textende dazu
    • HTTP überträgt Umlaute als ue, das ergibt ein Zeichen mehr
    • Das Zeilenende hinter dem Body zählt als zusätzliches Byte
    • Das ü braucht in UTF-8 zwei Bytes, und gezählt werden Bytes
  5. Was trennt in einer HTTP-Antwort die Header vom Body?
    • Der Header Content-Length selbst
    • Eine leere Zeile
    • Ein Semikolon nach dem letzten Header
    • Ein Doppelpunkt am Ende der Zeile

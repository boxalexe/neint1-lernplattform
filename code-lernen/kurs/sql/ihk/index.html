Prüfungs-SQL: Datum, EXISTS, UNION, ALTER und Rechte

Ziel dieser Lektion

Du beherrschst den Rest aus dem SQL-Auszug des IHK-Belegsatzes: Datumsfunktionen, Unterabfragen im FROM, COUNT(DISTINCT), EXISTS, UNION, ALTER TABLE, DROP TABLE und die Rechteverwaltung mit GRANT und REVOKE. Dazu wählst du Datentypen begründet und entscheidest zwischen relationaler und NoSQL-Datenbank.

Der Stoff

Der Belegsatz gibt die Syntax vor

In der Abschlussprüfung liegt ein Belegsatz bei, darin ein Auszug der SQL-Syntax. Die Lösungshinweise sagen ausdrücklich: Halte dich an diese Befehle. Die meisten kennst du aus den Lektionen davor, hier kommt der Rest. Dafür hat unsere Shop-Datenbank eine vierte Tabelle: ticket, die Supportanfragen der Kunden. Alle Beispiele hier laufen echt, bis auf die drei, die als „nur zum Lesen“ markiert sind.

Die Tabelle ticket

10 Tickets von 5 der 8 Kunden. Datum und Uhrzeit stehen als Text im Format JJJJ-MM-TT hh:mm, so lassen sie sich auch direkt mit < und > vergleichen.

Der Belegsatz nennt NOW(), YEAR(), MONTH(), DAY(), HOUR(), MINUTE(), WEEKDAY(), DATEADD() und DATEDIFF(). Merke dir bei DATEDIFF(Datumsteil, Anfang, Ende) die Reihenfolge: Das Ergebnis ist Ende minus Anfang. Vertauschst du die beiden, wird es negativ.

Erlaubte Datumsteile sind DAY, MONTH, YEAR, HOUR und MINUTE. Die Schreibweise stammt aus SQL Server, in MySQL heißt das Gegenstück zu DATEDIFF mit Datumsteil TIMESTAMPDIFF. In der Prüfung schreibst du, was im Belegsatz steht.

Die Falle am Jahreswechsel

Eine typische Prüfungsfrage: Welche offenen Tickets sind älter als zwei Monate? Naheliegend wäre MONTH(NOW()) - MONTH(erfasst) > 2. Das stimmt nur, solange beide Daten im selben Jahr liegen. Am Beispiel siehst du, warum.

Monate zählen: falsch und richtig

SQL
1
SELECT id, erfasst,
2
  MONTH('2024-01-15') - MONTH(erfasst) AS falsch,
Stichtag 15. Januar: 1 - 12 = -11. Über den Jahreswechsel wird die Differenz negativ.
3
  DATEDIFF(MONTH, erfasst, '2024-01-15') AS richtig
DATEDIFF zählt die Monatswechsel dazwischen: 1 und 2.
4
FROM ticket
5
WHERE erfasst < '2024-01-15';
Nur die beiden Tickets aus dem Herbst 2023.
In der Praxis

Statt NOW() steht hier ein fester Stichtag, damit das Ergebnis immer gleich bleibt. In einer echten Auswertung setzt du NOW() ein. Wer eine fremde Abfrage beurteilen soll, prüft genau solche Grenzfälle: Jahreswechsel, Monatsende, Schaltjahr.

Eine Unterabfrage als Tabelle

Eine Unterabfrage darf auch im FROM stehen. Ihr Ergebnis wird dann wie eine eigene Tabelle behandelt und braucht einen Namen (AS tbl). So rechnest du mit Zwischenergebnissen: erst je Kunde zählen, dann den Durchschnitt dieser Zahlen bilden. Zwei Aggregatfunktionen direkt ineinander wie AVG(COUNT(*)) sind nicht erlaubt.

Der Name ist Pflicht. Ergebnis: 10 Tickets durch 5 Kunden ergibt 2.
In der Praxis

EXISTS: gibt es mindestens eine passende Zeile?

EXISTS (Unterabfrage) ist wahr, sobald die Unterabfrage mindestens eine Zeile liefert. Welche Spalten sie liefert, ist egal. Die Unterabfrage darf auf die Zeile der äußeren Abfrage zugreifen (t.kunde_id = k.id), gedanklich läuft sie für jeden Kunden einmal. NOT EXISTS dreht das Ergebnis um.

In der Praxis

In der Praxis

Achtung

NOT IN hat eine Falle: Steht in der Liste der Unterabfrage ein NULL, liefert die ganze Abfrage keine einzige Zeile, denn ein Vergleich mit NULL ist nie wahr. NOT EXISTS ist davon nicht betroffen. Kann die Spalte NULL enthalten, nimm NOT EXISTS oder schließe NULL in der Unterabfrage mit WHERE kunde_id IS NOT NULL aus.

UNION: zwei Ergebnisse untereinander

UNION hängt die Ergebnisse zweier Abfragen untereinander. Beide müssen gleich viele Spalten mit passenden Typen haben. UNION entfernt dabei doppelte Zeilen, UNION ALL behält sie. Ein ORDER BY steht nur einmal ganz am Ende und sortiert das Gesamtergebnis.

1, 2, 3, 5, 7. Mit UNION ALL kämen 2, 5 und 7 doppelt.
In der Praxis

UNION führt Listen aus verschiedenen Quellen zusammen, etwa Kunden und Interessenten für einen Newsletter, oder aktuelle und archivierte Bestellungen.

Tabellen nachträglich ändern

ALTER TABLE ändert den Aufbau einer bestehenden Tabelle, ohne ihre Daten zu verlieren: ADD COLUMN fügt eine Spalte hinzu, DROP COLUMN entfernt eine, MODIFY COLUMN ändert ihren Typ oder macht sie zur Pflicht. DROP TABLE löscht die ganze Tabelle samt Inhalt, ohne Rückfrage.

Eine Spalte ergänzen und füllen

SQL
1
ALTER TABLE kunde ADD COLUMN email TEXT;
Neue Spalte. Alle vorhandenen Kunden haben dort zunächst NULL.
2
UPDATE kunde SET email = 'info@shop.de' WHERE email IS NULL;
Die Lücken mit einem Standardwert füllen.
3
SELECT name, email FROM kunde;
In der Praxis

Neue Anforderungen kommen in jedem Projekt: Plötzlich braucht der Shop die E-Mail-Adresse. ALTER TABLE erweitert die Tabelle im laufenden Betrieb, die Daten bleiben erhalten.

Eine Spalte zur Pflicht machen

SQL
1
-- nur zum Lesen: MySQL-Schreibweise wie im Belegsatz

Schritt 1: erst die Lücken füllen. Hans Jung hat keine Stadt, ohne diesen Schritt scheitert Schritt 2.

Schritt 2: Jetzt darf die Spalte Pflicht werden.
In der Praxis

Diese zwei Schritte in genau dieser Reihenfolge werden in der Prüfung abgefragt. SQLite kennt MODIFY nicht, deshalb läuft das Beispiel hier nicht. In SQL Server heißt es ALTER COLUMN statt MODIFY COLUMN.

Rechte vergeben und entziehen

Nicht jeder darf alles. Mit CREATE USER legst du einen Benutzer an, mit GRANT gibst du ihm Rechte auf eine Datenbank oder Tabelle, mit REVOKE nimmst du sie wieder weg. Merke dir die Richtung: GRANT … TO (an jemanden), REVOKE … FROM (von jemandem). SQLite kennt keine Benutzer, deshalb ist dieses Beispiel nur zum Lesen.

Ein Konto für den Support einrichten

SQL
1
CREATE USER 'support' IDENTIFIED BY 'Geheim#2024';
Neuer Benutzer mit Passwort.
2
GRANT SELECT ON shop.* TO 'support';
Lesen in allen Tabellen der Datenbank shop.
3
GRANT INSERT, UPDATE ON shop.ticket TO 'support';
Schreiben nur in der Tabelle ticket. Mehrere Rechte trennt ein Komma.
4
REVOKE UPDATE ON shop.ticket FROM 'support';
Das Ändern wieder entziehen. Einfügen bleibt erlaubt.
5
GRANT SELECT ON shop.kunde TO 'teamleitung' WITH GRANT OPTION;
Die Teamleitung darf dieses Leserecht selbst an andere weitergeben.
In der Praxis

Prinzip der minimalen Rechte: Jedes Konto bekommt nur, was es für seine Arbeit braucht. Wird ein Support-Zugang gestohlen, kann der Angreifer dann keine Kundendaten löschen.

Welche Rechte es gibt

Ist in einer Aufgabe von Schreibrechten die Rede, sind meist INSERT und UPDATE gemeint, je nach Aufgabe auch DELETE. shop.* heißt: alle Tabellen der Datenbank shop, shop.ticket nur diese eine.

Relational oder NoSQL?

In der Prüfung zählt die Begründung mit zwei Argumenten. Kundendaten und Aufträge mit festen Beziehungen, bei denen nichts verloren gehen darf, sprechen für relational. Daten ohne feste Struktur in großer Menge sprechen für NoSQL.

Vor einem Import: Datenqualität prüfen

Alte Daten aus einer Tabellenkalkulation einfach zu importieren, geht meistens schief. Prüfe vorher:
- einheitliche Formate: 1.7., 3.8.23 und 2023-04-13 in derselben Spalte lassen sich nicht sortieren oder vergleichen.
- einheitliche Schreibweisen: Müller und Mueller, Kein Ticket und Ohne Fahrschein meinen dasselbe, eine Abfrage findet aber nur eines davon.
- einheitliche Trennzeichen in Listen (, gegen ;).
- vollständige Pflichtangaben.

Die Folge schlechter Daten sind falsche Auswertungen. Abhilfe: ein Bereinigungsskript vor dem Import und für die Zukunft Auswahllisten statt Freitext, in der Datenbank also eigene Tabellen wie zustand oder vorkommnisart mit Fremdschlüssel.

Typische Stolperfallen

Gut zu wissen

Die Datumsfunktionen, LEFT und RIGHT laufen hier in der IHK-Schreibweise, obwohl die Datenbank im Browser SQLite ist. Die Plattform rüstet sie nach, damit du genau das üben kannst, was im Belegsatz steht.

Prüfe dich

  1. Was liefert DATEDIFF(DAY, '2024-03-01', '2024-02-27')?
    • -3, weil Ende minus Anfang gerechnet wird
    • 3, weil nur der Abstand der Tage zählt
    • 0, weil der März nach dem Februar kommt
    • Einen Fehler wegen der falschen Reihenfolge
  2. Warum ist MONTH(NOW()) - MONTH(erfasst) > 2 als Altersprüfung unzuverlässig?
    • Die Abfrage bräuchte dafür zusätzlich ein GROUP BY
    • NOW() darf nicht in einer WHERE-Bedingung stehen
    • Über den Jahreswechsel wird die Differenz negativ
    • MONTH liefert den Monatsnamen statt einer Zahl
  3. Ein Kunde hat drei Tickets. Wie oft zählt er bei COUNT(DISTINCT kunde_id)?
    • Genau einmal
    • Zweimal
    • Gar nicht
    • Dreimal
  4. Warum braucht eine Unterabfrage im FROM einen Namen wie AS tbl?
    • Der Name legt die Sortierung des Ergebnisses fest
    • Ohne Namen läuft sie nur einmal statt für jede Zeile
    • Ohne Namen werden doppelte Zeilen nicht entfernt
    • Ihr Ergebnis wird wie eine Tabelle benutzt und braucht einen Namen
  5. Was unterscheidet UNION von UNION ALL?
    • UNION verbindet Spalten nebeneinander, UNION ALL Zeilen
    • UNION entfernt doppelte Zeilen, UNION ALL behält sie
    • UNION ALL entfernt doppelte Zeilen, UNION behält sie
    • Nichts, ALL ist nur eine ältere Schreibweise davon
  6. Der Benutzer support soll in der Tabelle ticket nichts mehr ändern dürfen. Welche Anweisung passt?
    • REVOKE UPDATE ON shop.ticket FROM 'support'
    • REVOKE UPDATE ON shop.ticket TO 'support'
    • GRANT UPDATE ON shop.ticket FROM 'support'
    • DELETE UPDATE ON shop.ticket FROM 'support'
  7. Die Spalte stadt soll Pflichtfeld werden, einige Zeilen enthalten aber NULL. Was kommt zuerst?
    • Ein UPDATE, das die NULL-Werte füllt
    • Ein DELETE aller Zeilen mit NULL
    • Das ALTER TABLE mit NOT NULL
    • Ein DROP COLUMN für die Spalte stadt

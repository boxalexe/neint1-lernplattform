Vererbung, Polymorphie und Interfaces: Artikelarten und Zahlungsmethoden

Ziel dieser Lektion

Du leitest Klassen mit extends ab, überschreibst Methoden mit @Override, setzt ein Interface mit implements um und verstehst, warum derselbe Methodenaufruf je nach Objekt anders arbeitet und Code dadurch erweiterbar bleibt.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Gleiches einmal, Unterschiede gezielt

Der Shop verkauft inzwischen auch Software-Lizenzen zum Download. Eine Lizenz ist ein Artikel mit Name und Preis, nur Versand kostet sie nichts. Statt die Klasse Artikel zu kopieren, erbt DigitalArtikel alles von ihr und ändert nur, was anders ist. Das nennt man Vererbung. Der Test heißt ist-ein: Ein digitaler Artikel ist ein Artikel.

Danach die zweite Erweiterung: mehrere Zahlungsarten. Hier hilft ein Interface, damit der Checkout nicht für jede neue Zahlungsart umgebaut werden muss.

In der Praxis

Die if-Kette wächst mit jeder Zahlungsart, und jede Änderung kann die anderen Zweige kaputt machen. Mit dem Interface kommt Neues als neue Klasse dazu, Bestehendes bleibt unangetastet (Open-Closed-Prinzip).

Typische Stolperfallen

Achtung

Immer @Override über überschriebene Methoden schreiben. Ohne Annotation entsteht bei einem Tippfehler im Namen still eine neue Methode, und die alte läuft weiter.

Achtung

Von einem Interface oder einer abstrakten Klasse gibt es kein Objekt: new Zahlungsmethode() ist ein Compilerfehler. Erzeugt wird immer eine konkrete Klasse.

Tipp

Überschreiben (Override): gleicher Name und gleiche Parameter in der Unterklasse. Überladen (Overload): gleicher Name, andere Parameter in derselben Klasse. Beides wird in Prüfungen gern verwechselt.

Prüfe dich

  1. Artikel d = new DigitalArtikel(…). Welche Methode läuft bei d.versandInCent()?
    • Beide nacheinander
    • Die aus DigitalArtikel
    • Die aus Artikel
    • Keine, das ist ein Fehler
  2. Was ist der Unterschied zwischen Überschreiben und Überladen?
    • Überschreiben hat andere Parameter, Überladen ersetzt eine geerbte Methode
    • Überladen ist nur bei Interfaces erlaubt, Überschreiben nur bei Klassen
    • Es gibt keinen Unterschied, beide Wörter meinen dasselbe
    • Überschreiben ersetzt eine geerbte Methode, Überladen hat andere Parameter
  3. Warum ist new Zahlungsmethode() nicht erlaubt?
    • new geht nur bei Arrays
    • Zahlungsmethode ist privat
    • Ein Interface hat keine fertigen Methoden
    • Interfaces dürfen keinen Namen haben
  4. Was bedeutet super(name, preisInCent); im Konstruktor?
    • Die Attribute werden public
    • Ein neues Objekt der Oberklasse entsteht
    • Die Oberklasse wird gelöscht
    • Der Konstruktor der Oberklasse wird aufgerufen

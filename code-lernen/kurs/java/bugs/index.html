Bug-Arena: Fehler finden und beheben

Ziel dieser Lektion

Du findest in fremdem Code die fehlerhafte Zeile, ordnest den Fehler als Syntax-, Laufzeit- oder Logikfehler ein und wählst die richtige Korrektur. Genau so fragt die Prüfung: „Finden Sie den Fehler und korrigieren Sie ihn.“

Der Stoff

Fehlersuche ist Alltag

Ein großer Teil der Arbeit als Entwickler ist Debugging: Code lesen, der nicht tut, was er soll, und die Ursache finden. In der Prüfung heißt das „Finden Sie den Fehler in folgendem Code“.

Geh in drei Schritten vor:
1. Wo? Welche Zeile verursacht den Fehler? Das ist nicht immer die Zeile, in der es knallt.
2. Was für ein Fehler? Syntax-, Laufzeit- oder Logikfehler.
3. Wie beheben? Die kleinste Änderung, die die Ursache beseitigt.

Drei Fehlerarten

FehlerartWann merkt man es?Typisch
Syntaxfehlerbeim Übersetzen: Der Compiler meldet ihn, das Programm startet gar nichtif (x = 0), fehlendes Semikolon, falscher Typ
Laufzeitfehlerbeim Ausführen: Eine Exception bricht das Programm abIndex außerhalb des Arrays, Methode auf null, Division durch 0
Logikfehlergar nicht von selbst: Das Programm läuft, rechnet aber falsch<= statt <, == bei Texten, falsche Klammerung, fehlendes break

Die häufigsten Exceptions

ExceptionUrsacheBeispiel aus der Praxis
NullPointerExceptionMethode auf einer Variable aufgerufen, die auf nichts zeigtTicket ohne Bearbeiter: bearbeiter.length()
ArrayIndexOutOfBoundsExceptionIndex kleiner als 0 oder ab der Länge des ArraysSchleife mit <= über den Warenkorb
NumberFormatExceptionText lässt sich nicht in eine Zahl umwandeln„2 Stück“ aus einem Formularfeld
ArithmeticExceptionganzzahlige Division durch 0Durchschnitt über null Bewertungen

Ein Laufzeitfehler im Ablauf

Java
1
String eingabe = "2 Stück";
So kommt der Text aus dem Mengenfeld im Bestellformular.
2
int menge = Integer.parseInt(eingabe);
parseInt erwartet nur Ziffern. Hier bricht das Programm mit NumberFormatException ab.
3
System.out.println("Menge: " + menge);
Diese Zeile wird nie erreicht.
In der Praxis

Jede Eingabe aus einem Formular ist erst einmal Text. Wer ihn ungeprüft umwandelt, bekommt genau diesen Absturz, sobald jemand „2 Stück“ statt „2“ tippt.

Den Stacktrace lesen

Ausgabe
1
Exception in thread "main" java.lang.NumberFormatException: For input string: "2 Stück"
Erste Zeile: Art der Exception und Grund. Hier: Der Text ist keine Zahl.
2

Zeilen aus java.base sind Javas eigener Code. Den überspringst du.
3

Die erste Zeile mit deiner eigenen Klasse: Hier, in Zeile 2, liegt der Aufruf.
In der Praxis

Genau so steht der Fehler in der Logdatei eines Servers. Wer den Stacktrace von oben nach unten liest, findet in Sekunden die Zeile im eigenen Code.

Typische Stolperfallen

Tipp

Die Zeile im Stacktrace zeigt, wo es knallt, nicht immer, warum. Bei ArrayIndexOutOfBoundsException im Schleifenrumpf liegt die Ursache meist im Schleifenkopf darüber: ein Off-by-one-Fehler.

Tipp

Logikfehler meldet niemand. Hier hilft nur ein Schreibtischtest mit konkreten Werten: Was sollte herauskommen, was kommt heraus?

Achtung

Behebe die Ursache, nicht das Symptom. Ein try-catch um eine NullPointerException versteckt den Fehler nur.

Prüfe dich

  1. Ein Programm läuft ohne Meldung, zeigt aber eine falsche Summe an. Welche Fehlerart?
    • Compilerfehler
    • Syntaxfehler
    • Logikfehler
    • Laufzeitfehler
  2. Wo suchst du im Stacktrace zuerst?
    • In der ersten Zeile mit der eigenen Klasse
    • In der allerletzten Zeile des Stacktrace
    • In den Zeilen mit java.base
    • In der Zeile mit der höchsten Nummer
  3. Warum ist if (name == "admin") in Java ein Fehler?
    • admin muss in einfachen Hochkommas stehen
    • == vergleicht die Objekte, nicht den Text
    • == ist für Texte nicht erlaubt
    • Texte vergleicht man mit = statt ==
  4. Was löst eine NullPointerException aus?
    • Eine Division durch null
    • Ein leerer Text ""
    • Eine Zahl kleiner als null
    • Ein Methodenaufruf auf null

Kapselung: Lagerbestand und Passwort schützen

Ziel dieser Lektion

Du machst Attribute private, gibst Zugriff nur über Methoden mit Prüfung, erkennst, wann ein Setter fehl am Platz ist, und liest die Sichtbarkeiten im Code und im UML.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Warum Daten geschützt werden

In Modul 6 waren die Attribute von außen frei änderbar. Das ist bequem, bis jemand maus.lager = -15 schreibt: Der Shop hätte Ware verkauft, die nicht existiert. Kapselung heißt: Die Attribute sind private, und von außen geht es nur über Methoden. Diese Methoden prüfen die Geschäftsregeln, und zwar an genau einer Stelle, statt überall im Programm verteilt.

In der Praxis

Überverkäufe sind ein echter Schaden: Kunden zahlen für Ware, die nicht kommt, Stornos und schlechte Bewertungen folgen. Die Regel „Bestand nie negativ“ gehört deshalb in die Klasse selbst.

Die gekapselte Klasse im UML

Attribute mit - (private), Methoden mit + (public). Ein typisches Bild für gekapselte Klassen in Prüfungsaufgaben.

Typische Stolperfallen

Achtung

Nicht zu jedem Attribut gehört ein Setter. Ein Setter für das Passwort-Hash oder die Kundennummer würde die Kapselung sofort wieder aufheben. Nur ändern lassen, was sich fachlich ändern darf.

Tipp

Getter heißen getX(), bei boolean auch istX() oder hatX(); Setter heißen setX(…). IDEs wie IntelliJ erzeugen sie auf Knopfdruck.

Tipp

In Prüfungen heißt Kapselung oft auch Datenkapselung oder Geheimnisprinzip.

Prüfe dich

  1. Was bewirkt private vor einem Attribut?
    • Nur Unterklassen kommen daran
    • Das Attribut wird verschlüsselt gespeichert
    • Das Attribut kann nie geändert werden
    • Nur Code der eigenen Klasse kommt daran
  2. Wozu ist ein Setter mit Prüfung gut?
    • Das Programm läuft mit Settern merklich schneller
    • Ungültige Werte werden an einer Stelle abgewiesen
    • Damit wird das private Attribut wieder öffentlich
    • Er ersetzt den Konstruktor der Klasse vollständig
  3. Welches Zeichen steht im UML für private?
    • -
    • +
    • #
    • ~
  4. Warum hat Benutzer keinen Getter für das Passwort?
    • Strings haben keine Getter
    • Es soll die Klasse nie verlassen
    • Weil hash() private ist
    • Getter sind bei final verboten

Variablen, Datentypen und Casting: Preise, Mengen, Eingaben

Ziel dieser Lektion

Du wählst für jeden Wert den passenden Datentyp, weißt, warum Geld nie in double gehört, und wandelst Eingaben aus Formularen sicher in Zahlen um.

Szenario: Onlineshop

Ein kleiner Onlineshop für IT-Zubehör: Artikel mit Preis und Lagerbestand, ein Warenkorb, Rabatte und Versandkosten. Ab 50 Euro ist der Versand kostenlos.

Der Stoff

Daten brauchen einen Typ

Die Bestellbestätigung aus dem ersten Programm bestand nur aus festem Text. Ein echter Shop arbeitet mit Preise, Mengen, Namen, Status. Eine Variable ist ein benannter Speicherplatz, ihr Datentyp legt fest, was hineinpasst und wie damit gerechnet wird. In Java steht der Typ immer vor dem Namen und bleibt fest. Das wirkt streng, aber der Compiler findet so viele Fehler, bevor das Programm überhaupt startet.

Ein Artikel als Variablen

Java
1
String artikelName = "Funkmaus";
Text in doppelten Anführungszeichen. String mit großem S ist eine Klasse, kein primitiver Typ.
2
int lagerbestand = 35;
Ganze Zahl: Stückzahlen haben keine Nachkommastellen.
3
long preisInCent = 1999;
Geld in ganzen Cent. long reicht auch für Umsätze in Milliardenhöhe.
4
boolean lieferbar = lagerbestand > 0;
Wahrheitswert, direkt aus einem Vergleich berechnet: true.
5
char kategorie = 'Z';
Ein einzelnes Zeichen in einfachen Hochkommas, hier Z für Zubehör.
6
lagerbestand = lagerbestand - 2;
Zwei Stück verkauft. Neue Zuweisung ohne Typ, die Variable gibt es schon.
7
System.out.println(artikelName + ": " + lagerbestand + " auf Lager, lieferbar: " + lieferbar);
Mit + werden Text und Werte aneinandergehängt (String-Verkettung).
In der Praxis

So sieht ein Artikel in der Warenwirtschaft aus: Jede Spalte der Artikeltabelle in der Datenbank hat einen passenden Typ, und genau diese Typen kommen im Java-Code wieder an.

Die acht primitiven Datentypen

Daneben gibt es die komplexen Datentypen (Referenztypen): jede Klasse, allen voran String. Standardwerte bekommen nur Attribute; eine lokale Variable musst du selbst setzen, bevor du sie liest, sonst meldet der Compiler einen Fehler.

Deklarieren, initialisieren, Literale

Java
1
int bestellteMenge;
Deklaration: Typ und Name, noch kein Wert.
2
bestellteMenge = 3;
Erste Zuweisung. 3 ist ein Literal: ein Wert, der direkt im Code steht.
3
int maxProBestellung = 10;
Deklaration und erster Wert in einem Schritt: Initialisierung.
4
long umsatzJahrInCent = 4_250_000_000L;
Über etwa 2,1 Milliarden passt nur long. Das L macht das Literal zum long, die Unterstriche dienen nur der Lesbarkeit.
5
float rabattFaktor = 0.9F;
Kommazahl-Literale sind automatisch double. Für float braucht es ein F am Ende.
In der Praxis

Mengen, Grenzen und Kennzahlen stehen in jeder Bestelllogik. Der Jahresumsatz eines mittleren Shops in Cent sprengt int schnell, deshalb long.

Rechnen mit ganzen Zahlen: / und %

Java
1
int artikel = 17;
17 Artikel sollen verschickt werden.
2
int proKarton = 5;
In einen Karton passen 5 Stück.
3
int volleKartons = artikel / proKarton;
Zwei int teilen ganzzahlig: 3 volle Kartons, der Rest fällt weg.
4
int rest = artikel % proKarton;
Modulo % liefert genau diesen Rest: 2 Artikel.
5
int gesamtInCent = 3 * 1999 + 495;
Punkt vor Strich wie in der Mathematik: erst 3 Mäuse, dann der Versand.
6
gesamtInCent += 100;
Kurzform für gesamtInCent = gesamtInCent + 100 (Expresszuschlag). Ebenso -=, *= und für +1 einfach ++.
7
System.out.println(volleKartons + " volle Kartons, " + rest + " Artikel im Restkarton, " + gesamtInCent + " Cent");
In der Praxis

Versand in Kartons, 25 Treffer pro Seite in der Artikelsuche, Minuten in Stunden und Minuten umrechnen: / und % treten fast immer zusammen auf.

Warum double bei Geld gefährlich ist

Java
1
double gutschein = 0.10;
10 Cent Gutschein als Kommazahl.
2
double bonus = 0.20;
20 Cent Bonus.
3
double summe = gutschein + bonus;
Erwartet 0.3. Tatsächlich steht danach 0.30000000000000004 in summe.
4
System.out.println(summe);
5
System.out.println(summe == 0.30);
false! Der Vergleich schlägt fehl, obwohl auf dem Kassenbon 0,30 stehen würde.
6
long summeInCent = 10 + 20;
In ganzen Cent rechnet der Computer exakt.
7
System.out.println(summeInCent == 30);
true.
In der Praxis

Kassen, Buchhaltungen und Zahlungsanbieter rechnen deshalb in Cent oder mit BigDecimal. Ein Fehler von einem Bruchteil eines Cents summiert sich über Millionen Buchungen.

Exakt mit Nachkommastellen: BigDecimal

Java
1
import java.math.BigDecimal;
Ganz oben in der Datei.
2
BigDecimal preis = new BigDecimal("19.99");
Aus einem Text erzeugen, nicht aus der Kommazahl 19.99, sonst steckt der Fehler schon drin.
3
BigDecimal gesamt = preis.multiply(new BigDecimal("3"));
Gerechnet wird über Methoden statt mit + und *. Ergebnis exakt 59.97.
4
System.out.println(gesamt);
In der Praxis

BigDecimal ist der Standard in Bank- und Abrechnungssoftware, sobald Beträge mit Nachkommastellen nötig sind, etwa bei Zinsen, Steuern oder Wechselkursen.

Casten: Typen umwandeln

Java
1
int artikelAnzahl = 7;
Sieben Artikel im Warenkorb.
2
int warenwertInCent = 8990;
3
double schnittInCent = (double) warenwertInCent / artikelAnzahl;
Expliziter Cast vor der Division, sonst teilt Java zwei int ganzzahlig.
4
long gerundet = Math.round(schnittInCent);
Kaufmännisch auf ganze Cent runden.
5
long warenwertLong = warenwertInCent;
Impliziter Cast: von int nach long passt immer, Java macht es von selbst.
6
int anzeigeEuro = (int) (warenwertInCent / 100.0);
Von double nach int wird abgeschnitten, nicht gerundet: 89 statt 90.
7
System.out.println("Durchschnitt " + gerundet + " Cent, Anzeige " + anzeigeEuro + " Euro");
In der Praxis

Durchschnittspreis, Warenkorbanzeige, Kennzahlen im Dashboard: Ohne Cast liefert jede Division zweier int abgeschnittene Werte, und mancher „Rundungsfehler“ im Shop ist in Wahrheit ein vergessener Cast.

Formulareingaben umwandeln (EVA-Prinzip)

Java
1
// Eingabe
EVA: Eingabe. Was aus einem Formular oder von der Tastatur kommt, ist immer erst Text.
2
String mengeText = "3";
So liefert das Formularfeld die Menge: als Text.
3
String preisText = "19.99";
4
// Verarbeitung
EVA: umwandeln und rechnen.
5
int menge = Integer.parseInt(mengeText);
Parsen: Der Text "3" wird zur Zahl 3. Das Zeichen '3' ist intern der Code 51, nicht die Zahl 3.
6
double preis = Double.parseDouble(preisText);
Kommazahl parsen, mit Punkt geschrieben. Bei "abc" gibt es eine NumberFormatException.
7
long gesamtInCent = Math.round(preis * 100) * menge;
Sofort in ganze Cent umrechnen, dann exakt weiterrechnen.
8
// Ausgabe
EVA: das Ergebnis lesbar darstellen.
9
System.out.println(String.format("%d x %s Euro = %d,%02d Euro", menge, preisText, gesamtInCent / 100, gesamtInCent % 100));
%d ist eine ganze Zahl, %s ein Text, %02d zweistellig mit führender Null.

Integer und Double sind Wrapperklassen: Zu jedem primitiven Datentyp gibt es eine Klasse mit Hilfsmethoden wie parseInt. Weitere sind Long, Float, Boolean und Character.

In der Praxis

Jedes Bestellformular liefert Text. Erst parsen, dann rechnen, dann formatiert anzeigen: dieser Dreischritt steckt in jeder Eingabemaske.

Eingabe von der Tastatur mit Scanner

Java
1
import java.util.Scanner;
Ganz oben in der Datei.
2
Scanner sc = new Scanner(System.in);
Liest von der Tastatur.
3
System.out.print("Menge: ");
4

Immer die ganze Zeile lesen und selbst parsen. nextInt() lässt den Zeilenumbruch liegen und bringt das nächste nextLine() durcheinander.

In der Praxis

Konsolenwerkzeuge für Lager, Admins und Kassenterminals lesen so Eingaben. In Webanwendungen übernimmt das Formular die Rolle des Scanners, der Text kommt genauso an.

Jeder Kunde hat seinen eigenen Warenkorb mit eigenen Positionen (Instanz). Der Shop zählt die angelegten Warenkörbe aller Kunden gemeinsam (Klasse).

Konstanten und var

Java
1
final int VERSANDKOSTEN_IN_CENT = 495;
final macht die Variable zur Konstante. Name in GROSSBUCHSTABEN_MIT_UNTERSTRICH.
2
final int VERSANDFREI_AB_IN_CENT = 5000;
3
var anzahl = 3;
var lässt Java den Typ erkennen (hier int). Der Typ bleibt trotzdem fest.
4
String text = String.valueOf(anzahl);
Zahl in Text umwandeln, das Gegenstück zum Parsen.
In der Praxis

Feste Geschäftsregeln wie Versandkosten stehen als benannte Konstante im Code statt als „magische Zahl“. Ändert sich die Grenze, ändert man genau eine Zeile.

Zufallszahlen mit Random

Java
1
import java.util.Random;
Ganz oben in der Datei.
2
Random zufall = new Random();
Ein Zufallsgenerator.
3
int bestellnummer = zufall.nextInt(100000, 1000000);
Seit Java 17: 100000 bis 999999, also immer sechsstellig. Die obere Grenze ist ausgeschlossen.
4
int testmenge = zufall.nextInt(5) + 1;
nextInt(5) liefert 0 bis 4, plus 1 ergibt 1 bis 5.
In der Praxis

Testdaten erzeugen, Reihenfolgen mischen, Gewinnspiele. Für Sicherheitscodes wie Passwort-Reset-Links nimmt man SecureRandom, weil die Folge von Random vorhersagbar ist.

Typische Stolperfallen

Achtung

Geld nie in double. Kommazahlen sind im Binärsystem oft nicht exakt darstellbar. Rechne in ganzen Cent (long) oder mit BigDecimal.

Achtung

int menge = "5"; ist ein Fehler beim Übersetzen. Text muss erst geparst werden. Das ist gewollt: Der Compiler schützt dich.

Tipp

Variablen und Methoden schreibt man in camelCase (preisInCent), Klassen mit großem Anfang (Warenkorb), Konstanten in GROSSBUCHSTABEN.
